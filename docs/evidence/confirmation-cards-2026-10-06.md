# 确认卡片与原运行继续 · 2026-10-06

## 实际结果

在隔离数据和隔离 Hermes Home 中，使用本机已经配置的模型运行两段合成验收对话。执行器只配置 Wearing 生活工具，不提供设备、支付或外部账号连接器。

1. 模型提出“保存确认卡片验收 1”的卡片。浏览器点击确认，原 run 继续，创建并读回一条笔记；留下 `once` 回执。
2. 模型提出“保存确认卡片验收 2”的卡片。390px 浏览器点击“这次不执行”，原 run 继续返回拒绝结果；未创建第二条笔记，留下 `deny` 回执。

数据库核对：两个已返回结果的任务，各一张已回答回执，回执 run_id 与任务 run_id 相同；仅一条笔记。测试引擎随后停止。私有证据在 `.wearing/qa/confirmation-cards-20261006/live-check.json`。验收脚本最初误把生活记录的 JSON 字段当独立 SQL 列读取，修正后直接复核留存数据库，没有重复模型任务。

## 界面与失败路径

- 桌面实点确认；窄屏实点拒绝。390px 文档宽度为 390px，两颗操作按钮各高 46px，无横向溢出。
- pending / 已确认 / 本次不执行回执已实际显示。过期、同 ID 换动作、跨身份访问、并发点击、断网后禁止重发由测试覆盖。
- 真实验收环境关闭了本机设备而未配置云实例，导致辅助设备接口报错。这暴露了旧轮询会在读取对话前中断的问题；现将对话刷新前置，辅助查询独立处理。回归覆盖辅助连接失败仍读取对话、保持核心连接状态。
- Impeccable 静态检查最初指出新增颜色、字号和圆角偏离现有设计。已统一至既有色板和字号、圆角级别；新组件最终静态检查零发现，未添加忽略规则。
