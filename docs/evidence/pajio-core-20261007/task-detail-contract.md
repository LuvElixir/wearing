## 读取与控制

- GET `/api/tasks/{id}` 保留 task 字段，增加 `queued/queue_state/delivery`、events 和本任务 artifacts。未开始消息的操作由 `can_cancel/can_retry` 回执决定；旧服务仅兼容 `queued=true` 的撤回，缺字段不能推断 saved 可操作。恢复任务公开标题和正文仅为用户语义，详见 [恢复展示契约](recovery-presentation-contract.md)。
- 原生页面只投影已知过程状态，不展示 debug 事件或堆栈；返回内容可选择复制，成果进入既有原生下载校验/预览。
- 前台每8秒读取，手动刷新先 POST `refresh` 再读取；后台不轮询。未知运行、等待停止回执、明确停止分别展示。
- 停止/撤回须页面内二次确认，再读取原任务检查 run_id 和当前可操作状态，提交后读取原回执。断响应不会自动再次提交，也不显示为已经停止。
- 完整 Connection 与凭据在请求器创建时捕获，账户冻结、身份/页面切换均阻止迟到写入。每次 effect activation 有独立代数，StrictMode 重新挂载不能接纳上一轮的响应。
- GET 同一数据库快照返回正文与 `activity_receipt:{task_id,version}`。App 只在该结果已经渲染、仍处于前台且账户有效时确认这个精确版本；不另取新版编号去确认旧正文。旧版本确认不会清除较新结果的未读状态，失败不会伪装已读。
