# Wearing 个人引擎验收 · 2026-10-02

## 本次变更

- 统一产品身份：`src/wearing/identity.md` 同时供独立 SOUL 与请求说明使用。原默认 Hermes 身份已备份，用户模型配置及凭据保留。
- 新增独立托管入口：Wearing 直接运行固定上游 `APIServerAdapter`，不启动完整消息 Gateway、cron 或看板。仅保留健康、能力与 runs 接口；同步收缩能力声明。
- 版本化配置：关闭自动整理、后台自我改进及标题生成调用；配置迁移可重复执行，自定义身份冲突不静默覆盖。
- 页面将运行入口改为 Wearing，技术来源置于开源致谢。官方模型向导暂保留；尚未完成产品内模型/密钥配置。
- 修复重启时重新生成鉴权密钥的问题：上游持久运行记录的命名空间包含密钥哈希，随机换密钥使历史运行查询返回 404。当前专用凭据持久保存，损坏时明确报错，不自动轮换丢失原记录归属。

## 实测证据

使用用户已配置的 DeepSeek，先直接请求执行端（不附加 Wearing 请求说明），再通过独立测试数据库的 Wearing 服务，以及实际网页测试。用户正式数据库仍保持一条原草稿、零测试消息。

1. 执行端直接回答：“我是 Wearing，你的个人行动者。帮你把事情想清楚、动手推进，需要的时候替你跑腿办事。”
2. Wearing 连续对话正确介绍名字，追问 Hermes 时如实说明底层来源。
3. 询问电脑、手机与支付能力时明确说明尚未接通；没有进行任何设备或支付操作。
4. 第四轮正确回忆第一轮测试代号“卷袖二十八”。
5. 重启后，新的持久鉴权密钥保持一致，原 run 查询返回 200、输出一致；同一 session 继续回忆“靛蓝七十二”，身份仍为 Wearing。第一次失败及修复后的复测都保留在 JSON，不覆盖失败记录。
6. 实际网页输入“你是谁？一句话介绍自己就好。”，回答：“我是 Wearing，你的个人行动者，帮你把事情想清楚、也帮你动手做。”截图见 `screenshots/wearing-identity-20261002.png`。
7. 无鉴权的能力请求返回 401；Jobs、通用会话管理、技能、模型管理和跨 profile 路由返回 404。新独立进程集成测试也验证相同收缩范围，不消费模型额度。

具体 run_id、回复、用量及重启观测见 `personal-engine-2026-10-02.json`。无模型密钥或连接密钥。

## 验证边界

43 项 Python 测试通过，包括真实已安装引擎的 HTTP 契约检查、配置保留和凭据持久化；网页动效生命周期检查通过。wheel 与源码包构建成功，已核查 wheel 包含身份文件、独立启动器、配置迁移和第三方声明。真实对话是有限测试，不能保证任意模型或任意提示下身份永不偏离。

工具集仍为空，本轮完成的是产品身份、运行裁剪和恢复链路；电脑、手机、邮箱、号码、支付和沙盒实际执行尚未验收。接口保留审批和停止协议，但未以真实设备动作验证停止结果。不声称已经缩小依赖包体积；源码及许可证保留。Windows 尚未实机测试。
