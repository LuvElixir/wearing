## 独立隔离与服务器摊销

保留既定要求：每租户执行环境拥有独立内核（VM或经验证的microVM）。**共享控制面/共享硬件容量池不等于共享普通容器内核**，本次不改变架构。

- 首轮有限外测可沿现有“每租户独立VM”路径验证。不要把所有注册用户都直接乘以全天730小时；核算实际常驻租户、执行时长、保留盘、恢复耗时和库存风险。需要持续定时任务的用户也不能随意关机。
- 长期可评估有验证证据的microVM容量池：按峰值同时执行的沙盒数预留CPU/RAM，非运行租户保存加密状态。共享池能否省钱取决于实测资源用量、隔离/恢复和利用率，当前未完成这部分验证。
- 在普通CVM里再开microVM依赖宿主向来宾提供nested virtualization及可读写的 `/dev/kvm`，不能默认腾讯当前实例支持；需供应商规格确认与实例实测。Firecracker官方明确其KVM要求。[运行前提](https://github.com/firecracker-microvm/firecracker/blob/main/docs/getting-started.md)、[嵌套虚拟化环境](https://github.com/firecracker-microvm/firecracker/blob/main/docs/dev-machine-setup.md)。

腾讯CVM按量按秒计费、按小时结算，实例费、云盘、网络分别核算；支持阶梯的规格需按实际阶梯算。符合条件的STOP_CHARGING停止计算资源收费，保留云盘等仍计费，重启受库存影响。[计费模式](https://cloud.tencent.com/document/product/213/2180)、[价格规则](https://cloud.tencent.com/document/product/213/2176)、[关机计费](https://cloud.tencent.com/document/product/213/19918)。

`总基础设施费 = 控制面固定费 + Σ各VM/池的各阶梯计算小时×对应报价 + 云盘/快照/对象存储 + 公网出流量 + 监控/备份`。

`人均总成本 = 此用户模型+ASR+专属执行/存储/流量 + 共享固定费的分摊`。例如假设共享固定费为F、当月付费活跃人数N，平均摊销为F/N；F和N须用实际数据填，不代表当前实测值。按2Mbps持续屏幕流估算，1小时约0.9GB纯视频载荷；若经云中继，出流量可能是显著成本，实际还取决于编码、方向、协议和直连比例。

### 公司自有PC路径

用户有闲置Windows PC，具体CPU、内存、磁盘、虚拟化支持、网络上行和远程接入条件尚未核实；现在不估并发，也不假设能承载独立内核沙盒池。已有机器可省去对应计算资源的云租金，**模型、ASR等按调用付费不因此减少**。

`自有PC月增量费 = 实测平均功耗(kW) × 通电小时 × 电价 + UPS/存储折旧 + 异地备份 + 公网入口/中继流量 + 运维`，有需要时再计网络升级和备用机。备份、断电恢复、上行带宽、动态地址/运营商限制及安全公网入口仍需验证；成本和可用性不能只比较电费与CVM租金。当前先保留原云资源状态，不新购、不重装PC、不变更计费；等硬件/网络事实明确后选择部署路径。

## 并发与限额

- 当前源码对每身份网关限制1个运行任务；试用账本默认模型并发2、语音并发2，启用试用守卫时生效。它们是不同层的限制，不相加。
- DeepSeek当前账号级Flash并发上限2500，所有API Key合并计数；这是供应商上限，不能证明本服务能承载2500名同时执行的用户。[官方并发规则](https://api-docs.deepseek.com/zh-cn/quick_start/rate_limit/)。池容量应由 `峰值到达任务数/秒 × 平均任务占用秒数` 起算，再做尾延迟和资源压测；2C4G可承载几人尚无结论。
- `usage.py` 是试用**调用数**与语音时长限额，`usage_guard.py` 限单次输出8192 tokens；不是人民币预算。回执只提取输入/输出总量，未分缓存命中/时段，因此当前不能直接生成精确费用账单。真正的金额预算还要覆盖输入上限、模型价格版本、工具费用、缓存和未知回执。

结论：保留隔离要求和最小可用限额，先推进有限外测并采集实际用量。模型刊例价和当前腾讯账号报价已有证据，尚不足以承诺订阅毛利；停机保留盘/备份分项、ASR账号并发/资源包、搜索付费层、设备中继实际流量和应用商店渠道费仍待核实。
