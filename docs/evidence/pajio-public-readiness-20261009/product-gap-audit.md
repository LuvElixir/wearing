# Pajio 全面对外公开准备度与最初规划缺口

审计日期：2026-10-09。范围：产品定义、既有验收记录、共享服务及 `clients/mobile` 源码。此次只读审计，不构建、不操作 UI、不登录第三方账号、不操作云资源；仅新增本报告。Web / Desktop 继续由 ZCode 依据 App 与服务契约实现，不在本次修改范围。

## 结论

**Pajio 已具备较完整的 App 功能和局部真实 Agent 能力，但没有证据支持“陌生用户安装后即可稳定使用的公开产品”。** 当前主要差距已经从“页面有没有按钮”转向真实登录和实例供应、持续在线、物理手机授权及后台通知、完整账号退出与数据生命周期、以及最初承诺的真实资源取得和维护。

原定义不是通用聊天壳：它要求把资源取得、配置、实际执行、持续维护、接管、恢复和迁移连成产品。现有 Mac / Android 局部操作、真实模型局部验收不能替代上述完整链路；合成聊天导入和连接器列表也不能证明已经认识用户或接通其社交账号。

本报告不提供单一完成百分比。一个没有真实分发与账户入口的产品，即使大量组件测试通过，也不能据此计算“已完成 90%”。

## 证据如何读

| 标记 | 含义 | 不能证明什么 |
| --- | --- | --- |
| S | 当前源码或实施契约已存在 | 不等于已配置、部署或有人使用 |
| Q | 单元、集成、真实路由配合合成数据 / mock 供应商验收 | 不等于真实 OAuth、真实模型或真实外部动作 |
| N | 原生安装包在 iOS 模拟器上，使用隔离合成 QA 服务点击验收 | 不等于物理 iPhone 权限、后台、蜂窝网络或商店分发 |
| R | 既有记录中的真实模型、供应商、设备或数据库局部验收 | 只覆盖记录的版本、账户、设备和那条链路 |
| P | 正式部署、独立新用户、实际安装设备的端到端验收 | 本轮没有找到覆盖完整公开用户生命周期的 P 级证据 |

- **P0 公开阻塞**：公开提供核心服务前必须完成。
- **P0 能力启用前**：该具体能力对外开放或宣传前必须完成；关闭它不代表原规划已完成。
- **P0 收费前**：开始出售订阅前必须完成，免费公开不因缺少购买页单独受阻。
- **P1**：在稳定公开基础上继续实现的产品范围，不能冒充当前可用功能。

优先采用 10 月 8–9 日具体契约和验收。`docs/progress.md` 最新进度仍停在 10 月 7 日；`PRODUCT.md`、`docs/product-definition.md` 中按时间保留的旧状态存在“尚未实现”与后续已完成代码并存的情况。它们用于确认承诺，不能整段当作当前实现状态。

## 最值得立即实现的三项

### 1. 真实账户入口与实例就绪流程

把“填服务地址才能开始”变成可交付的公开入口：正式服务配置 / 可信邀请 → 真实登录 → 本人实例分配或就绪状态 → 首次认识 → 首个任务。处理登录取消、回跳失效、无实例、启动中、暂时不可用和退出。服务端继续决定 user / tenant / identity 绑定，不从客户端提交值推导归属。

验收必须是两个独立新账号、两个隔离实例，从物理手机首次安装开始；任务、文件、来源、通知、设备和注销回执均不能跨账号。真实 IdP、域名与发行签名属于外部配置条件，做完 UI 不能把此项关单。

### 2. 生产能力准入与发布预检

将已有散落的安全条件收成可信的部署预检和能力配置：TLS / 数据库权限、真实 worker、明确启用的用量上限、支持的模型传输、推送项目匹配、注销适配器、已验收连接器。未配置的能力应显示具体状态或不开放；服务端仍拒绝调用，客户端文案不是权限边界。开发 / synthetic 环境绝不能因 HTTP 200 被宣称为已生产就绪。

第一条必须跑通的真实价值链是：新用户交代一项有界研究 → 离开 App 并关闭开发 Mac → 云端继续 → 手机收到通知 → 回到正确任务看有来源的结果 → 用户能停止、导出或删除。这一链同时暴露常驻、额度、推送、会话和结果交付问题，优先级高于新增更多装饰与列表入口。

### 3. 公开用户的数据与退出中心

接通真实版本的隐私政策 / 服务条款与来源授权说明；在同一用户路径中列清“当前记忆”“停止使用来源”“移除来源正文”“完整账户注销”的作用范围。把注销 waiting / 未配置 / 不支持范围直接接到可联系的支持渠道和可追踪回执，补齐实际开放连接器的上游撤权；避免用户陷入永久等待或误以为历史副本也已删除。

部署前用一个独立真实测试账户完成登录、连接、导出、撤销和注销全过程；用另一个账户证明其数据未受影响。未来远程手机和密码管理器必须建立在这套归属、撤权和隔离基础之上；当前不应通过启用 `human_access_ready` 提前开放。

## 公开放行的最小证据清单

以下是需实际执行的验收，不是本报告已完成事项：

1. 两个独立真实账号和 VM；第三方登录、会话失效、越权与退出均通过。
2. iPhone 真实可分发包与 Android 正式签名候选；新装和升级成功且保留本人数据。
3. 开发 Mac 关闭后至少一次跨日任务 / 定时执行与恢复；结果状态来自真实运行。
4. 两平台实际通知到达、精确深链、拒权 / 退出 / 换账号不串消息。
5. 已开放输入 / 原生能力 / 连接器均完成真实授权、使用、失效、撤销和可恢复错误。
6. 试用上限在供应商请求前生效；未知写入不自动重试，额度耗尽仍可读 / 导出 / 停止。
7. 真实数据导出与完整账户删除在实际开放资源范围执行；保留范围、等待原因、人工渠道明确。
8. 第一个不由开发者代填配置的新用户独立完成有价值任务；耗时、失败和理解问题如实记录。少量可用性验收不被叫作市场验证或留存证明。

收费前另外完成订单 / 权益 / 退款 / 续订 / 恢复购买和对账。远程真机私密登录、社交采集、电话 / 支付 / 商业平台业务各自满足能力验收门槛后再开放；它们仍属于最初规划的未完成工作。
