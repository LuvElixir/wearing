# 聊天、完整月历与可靠交接 · 2026-10-07

## 交付范围

用户明确将「现在」改回「聊天」及对话气泡图标，日历需要完整月份，并继续推进“交代完能离开，回来能读懂进展”的核心能力。随后用户否定当前衣服飘动的角色动画，当前体验改为静态 3D 角色。保持钴蓝、近白和原 3D 卷袖角色，不重做品牌。

### 客户端

- 新体验与真实客户端使用共享聊天图标；内部 now/conversation 路由保持。
- 月历支持上月、下月、今天、选中日期的安排；导航图标取设备当地日期，非构建时写死。真实 Mobile agenda 和示例预览共享 MonthCalendar，全天/跨天按完整日期筛选。
- 月份切换及日期选择使用可中断过渡；操作立即更新，减少动态偏好受尊重。日历与笔记切换保留。
- 首页、Wearing 页与欢迎页使用定稿角色静态图，不再加载此次被否定的视频或解码器。保留页面、输入和反馈的轻量过渡，角色本身没有漂浮或呼吸动作。
- 首页主句为「你说，我来做。」输入栏保持「按住说话」，由主句解释价值、输入栏解释手势；产品定义同步明确语音输入、执行输出与可核对执行回执。

### 真实服务的普通聊天

新增 SQLite message_handoffs 与可选 request_id。只有新提交且执行端繁忙时进入已接收队列；空闲但首次离线仅保存，历史草稿不自动执行。

消息、任务和交接回执原子写入；相同身份/标识/正文返回原任务，正文冲突拒绝。客户端收到有效任务与 delivery 回执后才清输入；迟到响应不清掉后来输入，丢响应重试保持原标识。

队列按身份顺序交接，已有目标获得轮换机会。已入队后离线会退避并显示阻碍；服务重启先找原运行，未知状态继续阻塞而不重发。开始前可撤回，历史保留，并且用户自己的撤回不增加“新结果”。

进展四类：等你处理、正在推进、已排队、已有结果。正常排队不催促用户作决定，也不计入实际执行。Web 与原生 ActivityReview/decoder 一并接入。

## 隔离的实际 HTTP / 浏览器验收

服务位于 `.wearing/qa/durable-chat-20261007/serve.py`，独立数据库、身份「排队验收」、端口 8794。使用内存 HTTP transport 模拟引擎，真实 FastAPI / SQLite / 后台 poll / 浏览器 UI；不访问真实模型、设备和云资源。

1. 浏览器交代第一条合成事项，取得 fixture-1。
2. 繁忙时提交第二条，看到已排队；点击撤回，显示“没有开始执行”。
3. 第三条入队后关闭浏览器页；模拟第一条完成，后台自动启动第三条为 fixture-2。
4. 重启服务并重新打开网页，原 fixture-2 恢复查询，累计 start 仍为 2，撤回消息从未 start。
5. 再提交/撤回一条检查独立 waiting 分组；完成 fixture-2。最终 4 条消息中仅 2 条实际派发，另 2 条撤回。合成结果明确标识，不计入真实生活任务成功率。
