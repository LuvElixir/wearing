# Pajio 邀请制登录发布验收

日期：2026-10-10，时间均为 Asia/Shanghai。范围：官方入口、邀请码准入、账号创建、App / Web / 桌面连接方式，以及独立 C 测试空间的真实服务验收。

## 已交付的用户流程

- 新用户：使用邀请码 → 创建账号 → 进入自己的 Pajio。已加入的用户直接登录，不重复消耗邀请码。
- 官方服务固定为 `https://pajio.luckyloading.com`。正式客户端不显示服务器地址、endpoint、token 输入框；旧自定义服务凭据不会自动带入官方账号。
- App 使用系统浏览器、OIDC / PKCE、一次性回调和 SecureStore。自定义连接仅供显式开启的开发构建使用。
- 邀请码只能绑定一个事先准备好的空白独立空间。它不是登录凭据，也不自动创建 Linux 电脑或 Android 云手机。运维步骤见 [准入说明](../invitation-admission.md)。

## 真实服务验收

使用新建 C 测试空间完成一次真实注册，未复用 A / B 的账号或工作数据：

1. 无登录访问入口返回 303 到 `/join`；错误邀请码返回 422。
2. 有效邀请码进入创建账号页面；真实身份服务创建成功后返回 303，并建立 C 的网页会话，主页和状态接口均为 200。
3. 新浏览器不能再次使用已消费的邀请码；数据库准入状态为 `redeemed`，成员和所有者各 1。
4. 已有 C 账号通过真实 OIDC 登录；原生回调错误 PKCE 返回 400，正确交换为 200，重复交换为 400。
5. C 的唯一一次模型任务完成，回复精确为 `PAJIO_INVITE_C_OK`。账本记录 `api.deepseek.com / deepseek-flash`，16,495 input / 9 output / 6,144 cache-read tokens，与任务一致；持久记录为 1 次 API 调用、0 次工具调用。

模型费用 ¥0.021020 是运维估算，非供应商账单。终态 SSE 回放返回 404；本次使用持久任务、会话和调用账本交叉验证，不声称完整事件流回放已通过。详见 [C 空间记录](pajio-invitation-tenant-c-2026-10-10.md)。

## 服务边界与部署

- 控制库迁移至 `wearing_control_0003`，独立注册 broker 通过权限受限的 Unix socket 接入，不持有通用身份管理员权限。注册角色、清理角色、运行角色和迁移所有者分离；公网注册 provider 路径为 404。
- 身份服务保持全局自助注册关闭。邀请码注册只创建绑定不可变意图的账号；未知创建结果先核对原意图，不重复创建。邮箱、姓、名不作为注册必填项。
- 过期 OIDC 状态由独立定时维护身份每十分钟有界清理；不删除邀请码、成员、有效会话或身份账号。
- C 为新建虚拟机和独立证书 / 凭据，不克隆 A / B 的数据。已设开机自启，未为此重启虚拟机，冷启动仍未验收。
- 真实 WKWebView 曾因最终 `Referrer-Policy` 重复而把表单 Origin 变为 null。现仅精确邀请表单路由返回一个 `same-origin`，其余仍为 `no-referrer`；null / 缺失 / 外部 Origin 继续拒绝。公网头列表与真实桌面登录均已验证。
- 数据库升级后不能直接回退到仅支持 0002 的运行代码；回滚保留 0003 兼容层，或单独审查数据恢复。备份和私有变更意图均已保存。
