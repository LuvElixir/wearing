# Wearing 当前进度

核对日期：2026-10-03。依据：当前源码、8765 实际运行接口，以及已保存的真实模型/设备验收记录。这里区分「已经运行」「局部通过验收」「只有方案」，不使用无法核算的整体完成百分比。

## 当前交付是什么

Wearing 0.2 本地开发版。当前 Wearing 服务与 Hermes Agent 核心都运行在开发机，模型使用已配置的云端 DeepSeek 服务。网页和执行引擎当前可达，个人配置为 v6。未来按每租户独立 VM/microVM 部署的 SaaS 尚未运行。

## 接下来的收束方式

用户最新确认：**先推进产品工程，真实资源逐步积累。**资源取得较慢，不阻塞软件开发；状态分别记账。

1. **当前工程交付：**独立租户 Worker、OIDC 登录与固定实例路由已落到代码；平台 PostgreSQL 的 Alembic 迁移、独立网页/操作者/迁移角色和 FORCE RLS 已通过真实数据库及双用户 HTTP 验收。两套 Hermes Home 分隔另已验收。见 [租户运行](tenant-runtime.md)、[OIDC 入口](gateway-runtime.md)、[数据库配置](control-postgres.md)及[数据库验收](evidence/control-postgres-2026-10-03.md)。
2. **下一条云端闭环：**用户选择腾讯云首轮，已通过现有 tccli 验证账户、香港/新加坡区域、官方镜像、机型/配额及真实按量/包月报价，香港配置 DryRun 通过。工程新增腾讯查询/报价命令；没有创建 VM 或新增付费资源。正常每位用户一台独立 VM，先一台验证安装/持续运行/恢复，第二台只用于两租户隔离验收；随后接真实 IdP、生产 TLS/mTLS 与出站设备连接器。其他五家首批厂商仍为目标，火山/百度/Oracle 后续加入。见[腾讯云首轮方案](tencent-cloud-first-run-2026-10-03.md)与[多云范围](cloud-vm-selection-2026-10-03.md)。
3. **设备与持续工作：**接一次性配对、出站转发、动作账本、接管与断线恢复，验证不重复动作；然后完成网页关闭和跨天推进、通知及硬预算限制。
4. **真实资源积累：**邮箱、国内/海外号码、消费支付和收款各自记录实际资格、取得步骤、授权、续期/恢复与验收。邮箱先验证测试信收取与撤销重连；号码验证目标应用所需通信；支付/收款分别核对交易和账单。资源未取得时不点亮能力。

第一条用户价值验收应是「Wearing 使用你的真实资源持续推进一件明确的事，并给出可核对的结果」，不能以连接器数量、测试数量或界面完成度代替。
