# Wearing 生活工具

2026-10-04。首批在本地 `http://127.0.0.1:8765/` 可用；云端试验机保持暂停。

## 用户与 Wearing 共同使用

「今天」接住随手记录，展示今天的日程、待办和最近笔记。日历提供月、周和一周安排；可创建、编辑日程。清单支持分组、截止时间、完成和重开。笔记先提供短文本编辑。基础操作直接保存，不等待模型，也不需要外部日历账号。

每条记录可以「和 Wearing 聊这条」。对话输入保持自然语言，标题显示在输入框上方；稳定 ID、身份和引用版本在内部关联。Wearing 先读取最新记录，再修改同一条内容。生活记录、Agent 执行任务、长期目标分别保存，记录一个想法不会自动启动持续目标。

移除进入「最近移除」，支持撤销和恢复。当前浏览器的编辑/快记草稿使用按身份分隔的 `sessionStorage`；刷新或在工具之间切换可找回，关闭整个浏览器会话后的恢复不保证。这不是离线客户端数据库。

## 持久记录

`LifeBook` 使用既有私有 `wearing.sqlite3`，不建立第二个数据库。三种严格校验的记录：

| 类型 | 核心字段 |
| --- | --- |
| `event` | 标题、说明、起止时间、IANA 时区、全天标志 |
| `task` | 标题、说明、清单分组、可选截止时间、完成状态 |
| `note` | 标题、正文 |

共同字段包括稳定 `life_*` ID、`identity_id`、递增 `revision`、创建/修改时间和移除状态。`list_name` 目前只是待办分组，并非独立清单实体。

带时间日程必须包含 UTC 偏移，保存为 UTC；展示按记录时区转换。全天日期采用日期字段与排他结束日期，例如 10 月 4 日一天保存为 `2026-10-04` 至 `2026-10-05`。无效区间、类型不匹配字段和未知字段在写入前拒绝。

创建携带 `request_key`：同一身份同一键及相同内容仅产生一条记录；同键不同内容报冲突。更新、移除、恢复都必须匹配当前版本。过期客户端或迟到的 Agent 写入返回 409，不覆盖新版本。已移除记录不能直接编辑。记录与变更日志在同一事务提交，变更标记 `user` 或 `agent`。

快照在同一读事务内取得变化版本与记录。网页每 1.8 秒按版本检查，同身份多窗口最终看到同一状态；切换身份后丢弃旧身份迟到的响应。编辑冲突保留当前输入，让用户查看最新版本后重新编辑。尚未实现不同字段自动合并。

## 接口与 Agent

| 接口 | 作用 |
| --- | --- |
| `GET /api/life?after=…&include_deleted=…` | 当前身份快照；无变化时返回 `unchanged` |
| `GET /api/life/{id}` | 按当前身份读取一条 |
| `POST /api/life` | `{record, request_key}` 创建 |
| `PATCH /api/life/{id}` | `{revision, action, patch}` 编辑、移除或恢复 |

沿用既有入口鉴权、修改令牌及同源校验。请求体不能指定另一身份。跨身份记录返回 404。围绕记录创建对话时，消息与引用关联原子提交；对外人类原话不含工具名或记录 ID。

Hermes profile 9 整合 Wearing 的标准 MCP stdio 服务 `life_proxy.py`，固定传入租户数据目录与当前身份：

- `life_records`：读取记录，按需包含最近移除。
- `life_create`：创建带幂等键的严格记录。
- `life_change`：使用当前 revision 编辑、移除或恢复。

网页与 MCP 共用 `LifeBook`。身份由运行实例绑定，不交给模型选择。启动时发现三个工具后才宣告就绪。升级保留现有模型凭据及自定义配置；第三方 Hermes 源码不修改。

## 已验收与后续范围

真实模型创建笔记并由独立 API 核对；手动界面创建三类记录、两个窗口编辑冲突、完成/重开、移除/恢复、草稿刷新、原记录继续聊已验收。全套测试 383 通过，18 跳过。日历拖动/缩放已接组件与版本校验，实际拖动手势未单独验收。

图片与录音原件、后台 OCR/本地转写与真实模型整理现已接入，见 [随手输入](capture-input.md)。真实手机拍照与麦克风仍待验收。尚未接入系统提醒、Apple/Google 日历、系统分享、重复日程、搜索、原生安装包、离线副本、云端实时分发及记录事件的后台唤醒。保存日程仅代表记录成功，不承诺提醒已开启。当前多浏览器共用一个本地服务，不能表述为已完成所有设备的云端同步。

原始输入、媒体资产与整理失败重试已落地；接下来让真实移动拍照、麦克风及系统分享落入同一套记录。桌面包装与原生系统集成复用接口；恢复云端试验时部署相同代码，继续验收各端一致性。
