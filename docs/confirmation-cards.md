# 确认卡片

需要用户决定的执行动作，应进入可操作的确认卡片。普通的信息澄清仍在对话里进行；用户已经授权的常规步骤直接完成。卡片是一段执行的控制点，不是另建业务 workflow。

## 已实现

- 通用 `request_confirmation`：标题、具体动作、实际影响和确认按钮文案。手机权限、协议接受等场景可共用这一能力；相关信息不明确时先查清，不能用模糊的“继续”取得宽泛授权。
- 复用 Hermes MCP elicitation 与原 run 的 approval 接口。卡片决定返回给同一个运行；工具本身不代执行动作，不另发一条聊天冒充用户授权。
- 点击后整组按钮进入送出状态，成功后变成可展开的决定回执。允许、拒绝、过期、送达状态未知分别保留。确认仅表示授权，实际执行结果由后续工具与观察验证。
- 后端绑定身份、任务、运行、请求 ID 和原卡片内容。SQLite 原子领取决定；重复请求、旧请求、同 ID 换内容都不能重新执行。发送响应丢失时不盲目重发。
- 现有电脑操作卡沿用自己的 frame/revision/任务交托约束，设备权限、异常核对与目标核对表单共用卡片视觉。确认一个电脑动作不另叠加通用卡。
- 对话刷新优先于设备/设置/目标面板的辅助检查。辅助检查失败不会将真实 Agent 连接标成中断，或阻止下一张确认卡与结果出现。

## 精简卡片 · 2026-10-06

正常卡片只保留短标题、具体内容、必要影响与操作。取消重复的“需要你决定”标签、嵌套灰底影响区、确认按钮装饰图标和常驻提示；影响与正文完全相同时只显示一次。确认是唯一强调按钮，“不执行”为次要操作。异常与提交提示按需出现，费用、对象、权限范围仍直接可见，内容不截断。已决定的卡片收成一行可展开回执，按钮不会恢复。

移动端按钮至少 46px 高；桌面与 390px 网页布局已实测。拒绝或超时返回 card_closed=true，明确结束旧卡，不引导再次点击旧卡；工具本身不自动重新发起确认。当前模型偶尔仍补充“之后有新意图再处理”的多余句子，不能把指令约束当作每次都会精准控制文案。

## 目前边界

当前通用卡片等待沿用 Hermes 的 300 秒确认时限；超时不视为同意。卡片回执持久保存，但尚未提供系统推送、跨天离线点击后重新规划的决策收件箱。旧卡不能直接执行新动作。

工具与身份约定引导模型在需要确认时出卡；还不是针对任意 App 动作的语义权限防火墙，不能保证任何模型都不会遗漏确认。电脑关键动作另有执行端校验；其他连接器仍需逐步补齐对应机制与对抗测试。

系统必须由本人操作的权限、身份认证等，仍在原生界面完成，不能靠 Wearing 卡片代替。真实电话、邮箱、支付资源尚未接通；本轮没有付款、发信、协议接受或权限变更的业务验收。

网页与 App 内嵌对话共用组件；已检查网页桌面和 390px 布局，不等于 App 真机交互已验收。
