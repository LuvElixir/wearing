# 结果的设计质量

2026-10-06。用户指出演示看板的 UI 与交互仍粗糙，要求 dashboard、diagram、交互网页与 explainer video 都经过设计打磨。文件可以打开是技术条件，用户容易理解和判断才是交付目标。

## 通用创作过程

1. 明确用户看完后要判断的一件事，再选择媒介与构图。
2. 通过 `artifact_design_guide(presentation)` 按需读取 Wearing 视觉基础与对应媒介的审查用例。
3. 自由组织结果，首屏一个明确焦点，操作与反馈相邻，证据按需展开。业务任务不绑定固定模板。
4. 以同一份数据驱动结论、图形与明细；检查代表性输入和缺失/异常状态。
5. 有渲染工具时实际检查桌面与窄屏、操作及动画；没有时明确呈现未验收。
6. 保存不可变版本，交付简短结论与主要查看入口；修订延续原结果。

设计指引是创作辅助，不是自动审美认证，不增加用户逐项确认步骤。当前没有自动截图评审服务或独立的设计评分器；`artifact_publish` 仍仅确认文件保存，不能把模型自评写成已验证。

## 不同媒介的重点

| 媒介 | 信息组织 | 必须检查 |
| --- | --- | --- |
| Dashboard | 结论、主要图表、可核对明细 | 时间/单位/分母、比较尺度、缺失与零的区别、过滤后一致性 |
| Diagram | 真实边界、层级、方向、连线含义 | 路径可读、无错接或重叠、已知/推测可区分、窄屏读完整关系 |
| 交互网页 | 一个有价值的变量与近旁反馈 | 默认、变化、恢复、空值、异常、上下界、键盘和触控 |
| Explainer video | 问题、连续变化、后果与结论 | 对象连续性、音画语义、字幕节奏、起止画面、暂停/回看和摘要 |

视频目前仅提供规划指引，不能由现有 HTML 发布工具制作或播放成片。接入视频能力后还需独立验证素材、音轨、字幕、产物记录和实际播放。

## 当前样板

`design/artifacts/weekly-budget.html` 使用合成预算数据，由本轮人工设计修订：

- 先显示差额与总计，旁边提供同一预算的数字框与滑杆。
- 两条比较柱始终使用 0–1,200 元相同刻度，变化只移动图形，不改变布局。
- 小数按分计算；空值暂停结果，超出试算范围明确提示，恢复按钮回到原计划。
- 原始明细与假设折叠，手机改为单列；首屏标注示例数据。
- 保留原生焦点与键盘操作、读屏反馈，减少动态效果时关闭过渡。

这份样板展示期望的完成度，不规定未来结果只能采用这套布局。它不是新一次模型自动生成效果的证明；真实浏览器验收与工具集成结果见 [本轮证据](evidence/result-design-quality-2026-10-06.md)。


## 视觉基础与动态页面的分工

| 层 | 固定下来的内容 | 按需求变化的内容 |
| --- | --- | --- |
| 设计规范 | 语义颜色、排版层级、间距、圆角、焦点、动效、可访问性与证据呈现 | 本次重点和阅读顺序 |
| 基础控件 | 控件状态及操作手感；当前已提供数字字段、原生滑轨、关闭和折叠的统一皮肤 | 标签、范围、步进、单位、数据绑定 |
| 具体页面 | 自包含、身份隔离、版本与真实验证契约 | 布局、信息结构、图表、计算、内容和业务逻辑 |

`artifact_design_guide` v3 直接返回可复制的内联 `starter_css`、`starter_js`、`controls` 和 `style_contract`。生成器可以在这一基础上编写任意问题的结果页面；样式基础不规定用户必须按某套业务步骤行动。当前不是完整控件库，也不强制把所有需求塞进预算页面。

组合字段只保留外层焦点；滑轨统一轨道和滑块外观，保留原生键盘、指针、触摸与读屏能力。输入赋值、恢复和滑轨事件使用同一数据同步图形。尚未对所有浏览器和系统逐一验收。


## App 优先的宿主分工 · 2026-10-06

共享控件的唯一 CSS 源为 `src/wearing/web/result-controls.css`。网页宿主直接引用；Python 创作指引读取同一文件，生成器将所需样式内联到自包含产物。两者共享外观与交互，不共享 DOM、权限或业务状态。

- 关闭：44px 命中面、30px 视觉面、中性色悬停、局部按压；打开结果将初始焦点放在标题，键盘才显示关闭按钮焦点环。
- 折叠：原生 `details/summary`、线条箭头转向、完整触控行和读屏展开状态。
- 页面：先设计窄屏的主要判断与控制，桌面再扩展；模型自由选择信息结构、图表、交互与计算，不固定业务模板。
- 宿主：负责导航、身份、全局关闭、安全区及键盘。生成内容不重复绘制 App 导航，不直接操作真实账号或设备。

App 端当前是原生生活记录与嵌入网页对话的组合。此次增加 `host=mobile` 精简显示和原生加载/失败重试；原生结果路由、返回手势、草稿/试算状态连续性尚未完成。详见 [App 体验推进顺序](plans/app-first-experience-2026-10-06.md)。
