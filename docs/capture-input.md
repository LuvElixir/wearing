# Wearing 随手输入

初版流程记录：2026-10-04。语音服务已于 2026-10-07 改为豆包 Seed-ASR 2.0；接口与实际开通状态见 [接入证据](evidence/voice-cloud-asr-2026-10-07.md)。下述早期界面名称与验收范围保留作历史记录。

本地 `http://127.0.0.1:8765/` 的「今天 → 随手记一下」现已接入图片和录音原件。腾讯云试验保持暂停；本次没有恢复云机。

## 使用

写一句话，也可以添加图片、已有录音，或点击「说一句」使用浏览器麦克风。录完可以直接点「记下」：先结束录音、保存原件，再保存记录，不要求另外走一轮提交。每条最多四份原件，每份不超过 15 MB；浏览器录音最长三分钟。

记录类型仍由用户选择：笔记、待办、日程。默认先存笔记；选择日程时填写起止时间。「记下后，请 Wearing 帮我整理」默认开启，也可以取消，直接留住原件。图片可以由手机浏览器的拍照选择器提供；这还不是原生 App 或系统分享入口。

原件上传成功后，记录立即保存；识别和模型整理在后台进行。进度显示为等候、读取原件、整理、完成或失败。打开记录，在「原话与原件」中查看原图、听原录音及对照识别文字。整理只修改当前记录的标题和正文，保留用户选择的类型、时间和截止日期；不会因海报里有时间就另建一个日程。继续使用「和 Wearing 聊这条」可以要求 Agent 修改同一记录。

未提交但已上传的原件、文字草稿与整理选择在当前浏览器会话中按身份保留；刷新后恢复。正在上传的二进制或未结束的录音不承诺刷新恢复，会提示离开风险。后台失败不删除原件；可显式再整理，最多三次总尝试。用户在模型返回前修改或移除记录时，原记录优先，模型建议单独保留，不覆盖修改、不复活记录。

## 整合方案

- Mac 图片文字复用 [Apple Vision](https://developer.apple.com/documentation/vision/recognizing-text-in-images)；有 Tesseract 的其他主机使用现成命令。当前是 OCR，不是通用图片理解。
- 录音使用豆包 Seed-ASR 2.0 一句话识别接口（`bigmodel_nostream` / `volc.seedasr.sauc.duration`），先用 PyAV 转成有界的 16 kHz、单声道 PCM，再通过加密 WebSocket 上传。最多三分钟；原始文件只读。Whisper Small 及其引擎依赖已退役，不再自动安装或回退。
- 整理继续复用已配置 Hermes 的模型、Provider 和凭据解析。语音原件会发送至豆包语音服务进行转写；后续图片文字与转写内容才交给用户配置的整理模型。不要再把语音描述为离线或仅本地处理。
- iOS 开发配对已接入实时 PCM：同一采音源增量保存私有 WAV 原件，并通过带身份验证的局域网 WebSocket 桥边录边传。松手后终包确认才返回完整文字草稿，未提供实时字幕。Android、网页及普通云连接仍在松手后上传完整录音。真机采音和尾音验收状态见 [接入证据](evidence/voice-cloud-asr-2026-10-07.md)，不能以合成音频服务端成功替代真机结论。

配置转写：

```sh
uv sync --extra capture
uv run wearing capture configure --data-dir .wearing
uv run wearing capture status --data-dir .wearing
```

`configure` 隐藏输入豆包语音控制台的 API Key，不接受命令行明文密钥。也可加 `--browser` 打开五分钟、一次性的 127.0.0.1 配置表单。密钥保存在私有 `speech.json`（0600），或由 `WEARING_SPEECH_API_KEY` 注入；不要放入 App bundle、二维码或网页返回值。方舟 ARK API Key 不能替代语音 Key。控制台必须另外开通「流式语音识别 2.0 · 小时版」。`status` 和兼容命令 `prepare` 只检查本机配置与依赖，不证明账户额度和远端权限可用，不下载模型。

识别按供应商音频时长计费。失败不会自动重试、换供应商或发送历史录音；用户显式重试同一原件时，已有成功转写直接复用。子进程有 55 秒总上限，云端会话有 45 秒上限；取消/超时终止会话，不把迟到结果写给下一段录音。日志只记耗时，不输出录音路径、文本和密钥。

## 数据与恢复

继续使用租户私有 `wearing.sqlite3`，新增 `life_assets` 与 `life_captures`，记录本体仍为 `life_records`。原件以服务端 UUID 放在同一数据目录下的 `media/`，目录 0700、文件 0600；原始字节不重编码。文件名只作显示，不能指定存储路径。下载与创建沿用当前身份/租户入口，跨身份返回 404。

上传和捕获均带幂等键；记录、原话、资产引用、初始队列与变更回执在同一事务提交。整理状态通过同一变更流让网页更新；Agent 的 `life_records` 能读取同一条记录的来源和转写。后台只有一个受文件锁保护的消费者，同时只处理一条，正在执行用户任务时不启动新的整理。它不是无限常驻探索任务。

运行中断后，正在读取或整理的任务标为中断，等待用户显式重试，不自动重复可能已付费的模型调用。已读取的来源会复用，失败的剩余原件继续识别；旧 generation 和暂停后的迟到结果不能写入。备份和搬迁时必须一起保留数据库与 `media/`；恢复历史数据库快照与增量资产的自动协调尚未实现。

## 已验收与范围

本机真实验收了测试海报 OCR、合成中文录音解码/转写、DeepSeek 整理回写、原件逐字节一致、MCP 读取来源，以及 1280px 桌面和 390px 手机排版、刷新恢复与可选整理。转写仍有同音字误差，应对照原录音。浏览器录音已实现，麦克风真实录制、手机摄像头拍照、Safari 音频兼容和真实移动设备仍未单独验收。

尚未交付原生桌面/手机 App、HEIC 输入、系统分享、离线媒体副本、搜索、重复日程、系统日历、系统通知、原件永久删除/留存设置、云端媒体部署与跨设备离线同步。个人原件尚无自动清理规则；移除记录可恢复，原件继续保留。真实验收见 [本轮证据](evidence/capture-input-2026-10-04.md)。
