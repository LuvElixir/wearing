# Pro 研究到实施：决策矩阵

> 当前决定：2026-10-07 用户确认 **Pajio + 默认睡衣小熊**。下表已按本轮源码更新；名称与视觉以 [Pajio 品牌包](../../../design/brand/pajio/README.md)为准，最新验证以 [交付证据](../../evidence/pajio-delivery-2026-10-07.md)为准。研究建议不自动等于已实现。

2026-10-07 · App 候选源码核对 · 不替代测试、真机验收或市场验证

本记录对照 [Pro 完整审视](pro-review.txt)、[独立审视](independent-review.md)和当前源码，将建议分为三类。同一建议可以有已实现部分和后续部分；「源码已落地」只说明实现存在。Pro 自述未运行 App、未读取私有分支，其独立 token 检查也不能算作当前 App 的验证。

正式产品名为 **Pajio**，中文与英文界面同名。默认睡衣小熊与八套穿搭、轮廓字标、单星图标、日夜阅读主题已接入 App。旧技术包名、协议、存储键与安装标识继续兼容；新增 `pajio://` 并保留旧 scheme。本轮不是商标注册、应用商店发布或市场验证。

## 后续工程：已有基础与剩余缺口分开

| 工程事项 | 当前证据或缺口 | 完成时必须核对 |
| --- | --- | --- |
| 完整视觉与辅助字号适配 | 已桥接原生 fontScale 到聊天 WebView，正文、气泡、状态和搜索使用受控 CSS 尺度；输入高度随文字增长。浏览器宿主 200% 文本缩放检查无横向溢出；页面标题、辅助字级和控件仍有未统一尺度 | 实体 iPhone 日夜、超长中文、系统大字号和原件阅读继续验收；浏览器检查不能替代原生键盘、安全区域、系统字号与所有页面的辅助功能验收 |
| 非聊天输入收敛与真实离线反馈 | 紧凑入口已接入；Conversation 使用原生网络状态，VoiceComposer 的发送守卫检查离线、ready、sending 与非空文本；未知网络状态不伪报离线 | 源码和合成测试通过；仍需实体设备验证真实断网／恢复、启动未就绪、WebView 重载、系统中断。守卫存在不代表所有故障路径已真机通过 |

| 共享 activity 与执行端时间 | 已落地 [activity-store](../../../clients/mobile/src/activity-store.ts) 与 [共享 hook](../../../clients/mobile/src/use-activity-snapshot.ts)：Today、进展和任务复用身份／凭据隔离的内存首页快照，请求与轮询去重；后台或无人订阅时停止，恢复时刷新，失败保留过期快照；归档续页固定修订 | 统一缓存已经实现；checked_at 仍是读取快照时间、updated_at 仍是任务更新时间，均不是执行器心跳。执行端最近观察与离开期间变化摘要仍需独立数据证据，不能由轮询或缓存推断持续推进 |
| 完整任务档案与明确委托来源 | 服务端已提供 limit、bucket、cursor、revision、filtered_total 与 changed_since；任务和归档已提供加载更多，客户端拒绝不同修订和重复项的拼接。已补齐原先仅最近 20 项的可继续浏览路径 | 保留总体计数与当前页区别；对象级目标跳转、明确委托来源、完整任务详情及所有结果直达仍需单独完成。共享首页缓存已经接入；完整档案、委托来源与结果直达仍是独立合同 |
| 返回概览与恢复原上下文 | 当前概览可以呈现未解决和最近读取内容；没有因此获得完整离开期间变化追踪 | 增加事件或版本游标；冷启动、已有草稿、后台返回和深链接分别确定优先级；不突然打断阅读或跳页 |
| 记忆逐条纠正与来源 | 记忆详情已增加逐条纠正，真实选中条目和分区进入可编辑草稿；较长内容明确标注节选，由用户填写修正后发送，不自动改记忆 | entries 仍为字符串数组；来源、更新时间、适用范围、对象 ID、修改／停用／删除对检索与缓存的作用，仍需完整后端数据合同及验收 |
| 结果的主操作与继续调整 | 当前结果入口有版本、下载、依据和预览；任务列表「查看结果」仍先进入任务／原对话 | 可用产物直达，继续调整绑定产物 ID 与版本；返回保留位置；泛化评分按钮移除后仍保留实际业务核对。旧 HTML 字节与哈希不因换品牌静默改写 |
| 过期待决定事项的安全接续 | [confirmations.py](../../../src/wearing/confirmations.py) 已有过期与原运行绑定，不能当作跨时段决策收件箱 | 真实过期 UI、新意图重新核对对象／权限／条件、持久待决定记录与新的有效确认；旧 run/request 不复活。未知是否送达时先核对，不盲目重发 |
| 离开后的运行与通知承诺 | 本轮界面没有证明后台跨时段持续执行、系统推送、费用与权限失效恢复 | App 关闭、换网、服务重启、权限失效、决策超时和返回同一任务逐项验收；持久接收前不说「已接下」，无推送时只说结果留在这里 |

## 必须用户研究：代码与专家建议无法代答

| 待验证判断 | 研究方式 | 可以得出的结论边界 |
| --- | --- | --- |
| 窄人群是否有重复价值 | 按 Pro 建议先研究反复服务同一批客户的中文独立 B2B 顾问，以客户材料更新→沟通准备包→补资料修订为同一条路径 | 这是招募与任务切口假设，不能写成已确认市场；与用户现有方法及通用 AI 比较第二／第三次任务的交代、检查和返工 |
| 交代、返回、失败与授权是否看得懂 | 两轮各 5 人形成性测试，使用同类真实任务，包含断网、部分完成和过期决定 | 观察是否把本机保存当执行、已读当授权、过期批准当有效；4/5 在十秒内找到结果或阻塞只是继续修改的产品门槛，不是统计显著性 |
| 重复委托是否减少人工工作 | 20 位符合条件的用户、至少 60 次真实委托，配对记录旧方法与新方法的人工时间 | 48 次可用、第二周 8 人无催促复委托、人工时间中位数降低 30% 均是拟议推进门槛。未评价、退出、失败及人工支持保留在分母和报告中 |
| 默认小熊与简洁模式是否影响信任 | 当前采用默认睡衣小熊；研究时保持任务、文本、颜色、功能与交付一致，只改变角色，分别记录喜欢程度、能力理解、真实委托与结果使用 | 品牌决定不等于研究证明；不能从专家偏好、小熊好感或一张截图推出委托信任与留存 |
| Pajio 名称与单星能否清楚识别 | 名称及数字 VI 已选定；以同等素材进行听写、品类理解、次日回忆与真实产品触点识别，可用性另行专业核验 | 单四角星不独占一个品类，差异由轮廓、字标、留白、颜色和产品行为共同形成；名称采用不等于可注册结论或用户认知验证 |
| 阅读色彩是否舒适、导航是否合适 | 真实设备、亮度和环境光下连续阅读；比较首进／返回策略、找结果时间和对草稿的干扰 | 指定颜色对比度只说明明暗关系，不证明护眼、改善睡眠或长期舒适；漂亮截图不证明用户更会使用 |
| 是否愿意持续付费 | 权益、价格和真实服务就绪后观察知情付款及后续使用，记录任务成本和人工支持成本 | 喜欢、报名和口头愿付不是付费或留存；没有真实收款与续用证据时保持未验证 |

## 本轮采用方式

Pajio 品牌决定与本轮 App 源码已交付；上表的后续工程、真机验收和用户研究继续保留明确状态。品牌资产、源码、测试、真实委托和市场证据分别记录；Pro 的颜色包检查只属于该包。每次源码增量后更新本矩阵和对应交付证据，不将视觉完成写成全部产品能力完成。

网页与桌面仍由 ZCode 在自己的范围内推进，App 与共享状态合同只读；App-host 分支、身份隔离、草稿回执及既有不可变产物继续保留。
