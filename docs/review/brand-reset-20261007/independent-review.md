# 品牌与 App 重设计：独立审视

2026-10-07 · 源码与已提供截图审视 · 决策建议，非已完成的市场验证

阅读范围：`docs/plans/product-brand-ux-strategy-2026-10-07.md`、`clients/mobile/DESIGN.md`、`appearance.ts`、`PersonalHub.tsx`、`Mobile.tsx`、`AppBackdrop.tsx`、`AppDock.tsx`、`BottomNavigation.tsx`、交互 primitives。未改动 App 源码，未操作用户的浏览器。

## 结论

采用**安静、清楚、有余地的个人助理**方向。用户的任务、结果和判断占据视觉中心。辨识度集中在一个单四角十字星、字标和少量稳定的排版特征上。正文采用近中性背景和实色层次。默认界面可以完整成立，不依赖小熊、睡眠隐喻或服饰装饰。

“大气”落实为主次分明、较少容器、稳定对齐、适当留白和直接的操作；不扩大标题、会员卡和空白来制造气势。

当前的战略文档已经指出正确主线，但界面仍在展示上一轮的装饰成果。下一步应收敛实现，不再以更换一套氛围色作为整轮重设计。

## 1. 当前问题的实际来源

| 源码事实 | 对使用感受的影响 | 建议 |
|---|---|---|
| `PersonalHub` 首屏先显示主题选择、衣橱，再显示账户卡 | 产品首先解释外观，用户的事情与可用能力靠后 | 首屏账户摘要 → 连接与设备 → 数据管理；个性化放进二级页 |
| 账户卡 `minHeight:198`，位于另一个带边框的大卡内；包含渐变、圆环和虚线邮戳 | 装饰面积与真实账户信息不成比例；看起来像还没有实际权益的会员卡 | 取消内外套卡与邮戳；身份、连接状态、真实方案放进一个 88–112pt 的紧凑摘要 |
| 日间底色、正文、边框、按钮和光晕都偏黄棕；夜间同样存在暖色染色 | 整体有明显主题滤镜，阅读内容和产品功能缺少独立性 | 正文背景回到近中性；色彩只出现在少数动作、状态与品牌位置 |
| AppBackdrop 在全部页面铺底部暖光；大部分内容都用描边圆角卡 | 层层容器争夺注意力，卡片很难继续表达重要性 | 阅读区实色；普通列表用行与间距，只有结果、决定和弹层需要独立容器 |
| 底部“我的”使用小熊，聊天头像也依赖服装资产 | 用户在进入产品前已被绑定到角色品牌 | 导航用人物/账户符号；助手默认单星标记；角色由用户主动开启 |
| `Sparkles` / `WandSparkles` 分别承担品牌、记忆、技能符号 | 通用 AI 魔法图案重复；含义混淆 | 品牌单星只承担身份；记忆、技能、任务各用功能图标 |

颜色对比度达标只能证明指定文字组合的明暗关系。它不能证明长期观看舒适，更不能证明改善睡眠。用户已明确不喜欢当前配色，应以实机阅读比较判断新的候选。

## 2. 信息层级与交互

保留“聊天 / 今天 / 任务 / 记忆 / 我的”五入口，避免视觉重做同时再次改变用户已学会的定位。每页的第一屏只回答一个主要问题。

| 页面 | 第一屏要回答的问题 | 具体设计 |
|---|---|---|
| 聊天 | 我可以交代什么，现在接到哪一步了？ | 紧凑身份及执行状态，右侧搜索与设置；普通回复使用完整阅读宽度；交付结果独立成卡 |
| 今天 | 我离开后有什么变化？ | “需要你决定”优先，其次新交付；最多三项重点，日历从这里进入。没有变化时安静收束 |
| 任务 | 这件事现在怎么样？ | 活跃任务优先，已完成归档；点入后能看当前阶段、最后更新、已有结果与下一步 |
| 记忆 | 助理依据哪些信息理解我？ | 关于你的摘要、最近更新、可读文件；每项可查看来源与纠正方式；不让原始目录抢首屏 |
| 我的 | 我连接了什么，能控制什么？ | 账户摘要、连接/设备、数据与隐私、外观；不常驻输入栏 |

聊天内取消普通回复底下的“核对结果”“记成目标”。研究用的满意度和有效交付确认放在研究流程中；实际操作使用“打开报告”“修改要求”“保存文件”“查看日程”等对象明确的文案。确需建立持续目标时，在任务详情提供，先解释将如何持续执行。

进展只保留一个主要入口。聊天页顶部可显示“正在整理会议材料”；消息下方仅有与这一条回复直接相关的短回执，如“任务已接下”“记忆已更新”。不要再放同一份总进展卡。

保留已经跑通的录音、ASR、草稿和 WebView 主题桥接。调整视觉不能改变长按、取消、转写后编辑再发送的授权语义。正常转写反馈就在输入区，错误可展开详情，技术异常进入诊断日志。

## 3. 视觉候选：矿物中性色

这是一套可实现的候选，适用于此次设计比较；不是健康建议或唯一正确的色彩。

| token | 日间 | 夜间 |
|---|---|---|
| canvas | `#F5F5F2` | `#151A19` |
| surface | `#FFFFFF` | `#1E2523` |
| soft | `#ECEEEB` | `#28312E` |
| ink | `#202625` | `#E9EDE8` |
| muted | `#606B68` | `#A8B4AD` |
| accent | `#365F54` | `#B2D4C4` |
| onAccent | `#FFFFFF` | `#17382E` |

彩色仅用于关键主操作、选中标识与必要状态。绿色不可铺满整屏或成为每个图标的颜色，避免产生健康/冥想产品的误读。账户品牌区域与图标默认 ink 单色。

使用相对亮度公式，对以上不透明 sRGB 候选计算得到：

| 组合 | 日间 | 夜间 |
|---|---:|---:|
| ink / canvas | 14.08:1 | 14.86:1 |
| muted / canvas | 5.06:1 | 8.21:1 |
| muted / surface | 5.53:1 | 7.29:1 |
| muted / soft | 4.74:1 | 6.24:1 |
| onAccent / accent | 7.19:1 | 7.98:1 |

这些计算未覆盖透明叠层、图片、focus 边界、错误色与全部控件，也不等于完整辅助功能验收。首次跟随系统，保留既有明确选择。对比度、字号和主题切换全部通过后，再做长内容阅读测试。

排版：正文 17pt、行高 26–28pt；页面标题 30–32pt、中等字重；卡标题 18–20pt；关键辅助信息至少 13pt。统一左对齐基线和 20–24pt 页面边距。普通内容卡 16–20pt 圆角、浮层 24–28pt；不为所有行加卡、不为所有图标加圆底。44pt 点击区域独立于图标视觉尺寸。

## 4. 单星标识系统

采用一个四角十字星：单个中心、上下左右四个尖端、内凹柔和曲线、垂直轴可略长。24×24 画布，中心在 12,12；外围留 3–4px 安全距离。优先做实心单色版本，线框仅在需要匹配线性图标的场合使用。小尺寸要独立调整，避免尖端断裂和中心糊成圆点。

只出现一个星，不加卫星、小加号、魔法棒、轨道或星群。提供 16/20/24/32/48 的光学尺寸检查。不要让装饰标记看起来可以点击：账户卡右上若没有行为，可以直接移除；若承担品牌签名，只读且不进入辅助焦点。

品牌星不等于功能图标。“添加”仍是加号，“搜索”仍是放大镜，“设置”仍是齿轮；“技能”可用 Layers 等稳定功能图标，“记忆”继续使用带文字的记忆标识。默认助手头像可用单星，但不每条回复都重复一个。

## 5. 小熊的决策架构

**建议默认不出现角色。** 保留现有资产与用户已明确选择，不删除，不继续投入新服装。外观二级页提供“简洁 / 小熊”两种表达，切换不影响任何能力；导航、错误、付款、权限与结果中不放玩偶。

这属于当前设计判断，还需要验证。比较实验必须保持任务、文本、颜色、交互和能力一致，只变角色。观察用户是否敢于交代真实任务、是否正确判断产品能力、是否能找到交付结果，以及实际重复委托；“我喜欢这个熊”的反馈单独记录，不能作为主品牌成立的证据。

角色只有在提升核心任务体验且不降低专业信任时才上升为主要识别。不引入喂养、亲密度和回访义务。

## 6. 命名标准与当前建议

产品名和角色名分离。当前不要把新的中文候选直接写入包名、域名和正式账户体系。`Wearing` 与现有执行价值关系弱，可以退出对外品牌；此前“余刻”仍只应是测试候选，它也有被理解为时间管理/冥想的风险。

下一轮候选围绕“事情有着落、可放心交托、留回自己的时间”，不限定睡眠、日历、熊或穿着。控制在三名以内，每个候选使用相同产品说明和任务，不让某一款获得更漂亮的视觉加成。

筛选权重建议：口头复述与拼写 25%、隔日记忆 20%、与实际价值的联系 20%、无错误类别联想 15%、可用性核验 20%。这是研究排序工具，不是客观市场评分。商标、商店同名、域名和主要语言歧义需另行核验；若可用性失败即淘汰，无论分数高低。

主表达建议保留“交代给我，时间留给你”，它能覆盖白天夜晚。只有已持久接收、具备离线执行能力的任务，才可以使用夜间“先休息，进展我会留好”的场景文案。

## 7. 代码优先级与验收

1. `navigation-icons.tsx` 或独立品牌组件增加单星；替换品牌位置 `Sparkles`，技能位置改为功能图标。检查 16–48pt 和明暗主题，不顺手修改任务状态语义。
2. `appearance.ts` 与 App 宿主 CSS 同步近中性色；`AppBackdrop` 改实色；使用既有主题桥接保留聊天状态。不要全站替换影响 ZCode 负责的常规网页。
3. `PersonalHub.tsx` 账户信息前置，主题/衣橱下沉；压缩账户装饰；保留连接、设备、记忆和真实权限入口。
4. `BottomNavigation` 默认我的使用账户图标；助手默认单星。角色设置需要身份隔离与持久化，迁移不覆盖用户明确选择。
5. 聊天/进展结果先去重，再统一布局；结果和需要决定的事项优先，普通问答不进入交付计数。
6. 逐页检查日夜、超长中文、系统大字号、键盘、断网恢复、转写错误、后台后返回。完成后再把已验收 App 契约交给 ZCode。

视觉验收必须覆盖：聊天长文、今天有/无数据、任务执行/失败/待决定、记忆文件、我的/设置、语音转写与键盘。至少观察一次由用户真实完成的“交代—离开—返回使用结果”。漂亮截图、单色对比度和构建通过分别记录，均不能替代这个行为验收。
