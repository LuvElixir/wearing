二、核心定位：不是更全面的聊天入口，而是可接续的个人委托
推荐定位

个人 AI 执行助理：接收具体委托，在已有授权和可用能力内处理，把进展、需要决定的事项和可使用的交付留在同一件事里。

这里的产品价值不是“能调用很多工具”，而是用户能回答三个问题：

这件事是否被接收？现在需要我做什么？已经有什么可以拿来用？

语音是降低交代成本的方式，记忆是减少重复交代的方式，任务页是管理责任的方式；它们都不是独立的主卖点。

最窄的首批任务人群

我建议先选：

反复服务同一批客户、每周至少三次准备项目沟通材料的中文独立 B2B 顾问。

唯一主线是：

客户资料更新 → 为下一次项目沟通整理准备包 → 补充资料后继续修订。

一次交付包含一页沟通提纲、相对上次的变化、待确认问题，以及能回到材料的依据。第一阶段不代发邮件、不采购、不控制客户业务系统。

选择这个切口，是因为它能同时检验你们希望建立的几项价值：手机上快速交代、跨次上下文、离开后返回、版本修订、交付可用性。这是我推荐的试验切口，不是已经被市场证实的需求。

资料支持范围必须与真实解析能力一致。现有源码不能证明任意 PDF、Word 都能被正确读取；本轮至少应补通目标用户最常用的一种文件格式。优先核验文本型 PDF，扫描件另行验收，不能以选择器接受文件代替解析成功。

我会挑战的现有假设

“会前准备、资料比较、事项跟进”不宜作为三个并列市场同时验证。 它们可以组成同一个重复工作流程，但分别做演示会掩盖用户到底为什么回来。03 中的验证方法总体谨慎，首批范围仍偏宽。

“个人助理”不意味着首屏要管理整个人生。 日历、健康、邮箱、设备、技能全部上首页，会提前制造授权和理解成本。首批用户应能用一份资料开始，而不是先接好全部账号。

“自主执行”不等于每一步都需要用户确认。 用户已经交代并授权的低风险步骤应直接推进；真正需要决定时，再展示具体动作和影响。

“有长期记忆”本身还不足以构成差异。 必须证明第二次、第三次处理同一客户材料时，用户少交代、少核对、少返工。若同样资料直接交给通用 AI 更快，你们尚未建立足够的切换理由。

三、品牌、角色与命名
品牌推荐：有能力感，但不人格表演

推荐的品牌行为是：说清正在做什么，保留已完成部分，承认具体缺口，不要求用户照顾助理的情绪。

本轮主界面取消默认小熊、衣橱入口、睡衣主题名称和拟会员卡。已有资产及选择数据保留，不需要删除；角色实验可以留在研究版本中。

这并不是“小熊会降低信任”的事实结论，目前没有这种证据。我的取舍依据是：它尚未证明有助于委托，却已经占用了首屏和实施预算。本轮也不必为了折中，先建设一套完整的可选角色系统。

“晚安”退出主定位。它可以是未来某次使用情境中的一句话，不应主导全天产品的颜色、角色和功能组织。

单个四角星的使用方式

推荐一个实心、纵轴略长、四个内凹弧面连续的四角星。以 24×24 网格设计，图形约占宽 16、高 20；不附小星、不发光、不加眼睛、不循环闪烁。

它只承担品牌识别，不承担“技能”“成功”“运行中”等功能语义。功能图标继续用一致的线性图标：聊天、概览、任务、记忆、个人。Sparkles 和 WandSparkles 不应被批量替换成另一种“AI 魔法图标”；技能用工具图标，简报用文档图标。

3. 图标与动效

功能图标统一 22–24，线宽 1.75，默认不加圆形底座；选中状态同时使用字重或形状变化，不只改变颜色。

按压反馈 80ms，局部内容进入 180ms，浮层过渡 220ms；普通 Tab 切换不做整页上浮、缩放或依次入场。减少动态效果开启后取消位移和循环动画。任务没有新观察时，不用持续闪动的星形营造“仍在工作”。

首次外观跟随系统，保留用户已有明确选择。原生主题与 WebView 主题一同变化，不刷新对话。

记忆	当前空间与读取时间 → 关于你／工作经验 → 可读条目与逐条纠正 → 资料文件入口	删除“越了解你越能帮你”的大介绍卡。记忆与工作文件分开，不能把上传文件自动当成确认过的个人事实
我的	当前空间、切换入口、真实连接摘要 → 连接与权限 → 资料与文件 → 数据与隐私 → 外观、高级设置	不显示会员凭证，不显示衣橱。模型配置和服务地址进入高级设置；没有公开账户登录时，不伪装成账户资料页

账户区域建议从现有大卡改成 约 104–120 高的两行信息块：第一行“当前空间＋切换”，第二行“连接状态＋查看详情”。没有轨道、渐变、徽章，也不重复显示两次“个人空间”。

打开 App 与返回策略

首次使用进入聊天。有过委托之后，无未发送草稿的冷启动优先进入今天；普通后台返回仍恢复原页面、滚动位置和输入状态，不突然跳页。已有草稿、录音恢复或明确深链接时，以这些上下文优先。

这是值得实施后测试的导航判断，不是已经证明最优的规则。要观察它是否减少找结果的时间，同时有没有打断连续对话。

非聊天页不常驻完整输入栏。今天、任务在标题区保留“交代一件事”；点开后使用同一个输入控制器。我的、设置、权限页不显示聊天输入。这里要改变可见性，不要销毁草稿和录音状态。

六、核心 UX：把“可以离开”做成真实合同
委托：表达在前，结构整理在后

用户可以直接说：

明天下午和客户复盘，按这两份材料整理上次没定的问题和新增变化，做成一页提纲，不对外发送。

不先要求选择任务类型、建项目或填写完整 Brief。Agent 可以提炼目标、资料和限制，但只有缺失信息真的阻碍下一步时才追问。

附件在输入区明确展示名称和状态：已选到本机、上传中、已上传、读取失败。不能用一个勾同时代表“文件选中”和“Agent 已理解”。

语音维持现有合同：按住录音、松手转文字、可修改、显式发送；另提供点按开始／结束的可访问操作。录音是否开始只能由实际录音状态驱动，不能在手指按下时提前显示“正在听”。Seed-ASR 保持现有集成，本轮不因视觉改版替换供应商。

接收：发送动作与执行接收分开
用户看到的状态	必须成立的事实
草稿已保存在本机	本机持久化成功，尚未委托
正在发送	请求进行中，不能先说已经接下
已接收，排队中	服务端已有持久任务／交接回执
已开始处理	执行端已接受运行
暂时不能确认是否开始	响应丢失或状态不明；保留原请求，不另开任务

“可以离开”提示只在持久接收之后出现，并说明实际运行条件。例如本机服务模式需要执行电脑继续运行。仅 connected === true 不足以承诺后台会持续执行。

当前没有系统推送时，文案应是“结果会保留在这里”，不能写“完成后通知你”。

返回：先看变化，不重新读整段聊天

本轮可以直接利用未读结果＋未解决事项形成返回概览，但不能宣称已经实现完整的“离开期间变化摘要”。精确变化追踪需要额外的事件或版本游标。

交付卡使用固定结构：

自然标题 → 一句结论 → 可打开的产物 → 版本／必要来源信息 → 一个主操作。

例如“查看准备包”是主操作，“继续调整”是次操作。点击查看只写入已读回执，不自动批准、不自动验收。

完整结果使用全屏阅读页，保留回到原处的位置。旧版 HTML 是不可变快照，品牌更新不能静默改写它的字节和哈希；新产物再从生成规范中落实新视觉。现有产物元数据已经分别记录文件、渲染和内容检查状态，这种区分应在新界面中保留。

失败：给出保留部分与下一步

失败界面固定回答：

哪一步没完成；哪些内容仍可使用；下一步怎样恢复。

“第三份材料无法读取，前两份比较已保留”应同时提供“查看已有比较”和“补充材料”。不要把整个页面替换成错误插画。

连接中断、执行结果未知和明确失败必须区分。ambiguous / connection_lost / unknown 不提供会重新触发现实动作的“再试一次”；先核对原运行。停止也是请求，执行端未确认前显示“正在停止”，不能提前宣称所有动作已经终止。

授权：系统权限、任务范围和具体动作是三件事

系统权限继续在原生界面完成；任务范围来自用户本次交代；超出范围的实际动作再用确认卡。卡片直接展示对象、内容、影响及有效性，不用一个抽象“继续”取得宽泛批准。

过期恢复分两步实施：

现在就可以把旧卡收成“已过期，未执行该授权步骤”，保留资料与计划，并提供“重新检查并继续”的明确新意图入口。

真正支持几小时后再决定，需要持久保存待决定事项；用户返回时重新核对对象、权限和可能变化的条件，再产生当前有效的确认。业务上的同一件事可以延续，执行层旧的 run / request 不能复活。

另外，当前通用确认主要依赖工具与模型约定，不是覆盖任意 App 动作的硬性权限防火墙。新 UI 不能据此承诺所有外部操作都绝不会漏掉确认。
