# Pajio 首次认识与上下文建立

2026-10-09。适用中国用户、iPhone 优先的原生 App；同一后端协议供 Web / Desktop 使用。本文记录产品判断和验收标准，不代表已完成用户实验。

同日补充：连接研究已扩展为官方接口、本人登录的物理真机、用户选定分享/导出三条路线。详见[国内上下文来源与真机连接](pajio-context-sources-2026-10-09.md)及[远程人工接管合同](pajio-physical-device-access-2026-10-09.md)。本文下面的六步流程记录已交付首版；新增微信归档导入、社交账号资料读取及实时遥控仍是下一阶段开发项，不能将方案视为已实现。

## 目标与取舍

用户首次登录后，通过点选和可选的数据连接，让 Pajio 得到一份小而可靠的初始上下文。用户无需输入文字、陈述当前目标或理解 Agent 的能力分类。进入正式产品后才开始自由输入。

评价每一个问题和授权入口时，依次检查：它会改变哪项服务、信息是否可靠、多少目标用户有这份数据、实际完成需要多少步骤。注册资料完整率和授权数量不作为成功指标。

首版采用可回退、可跳过、可中断恢复的完整流程，延续现有 App 的近中性日夜主题、文字层级、睡衣熊和可访问控件。已使用的账户通过“我的”主动进入，新空账户才推荐自动进入。已有分享、通知、文件、登录恢复和注销流程优先完成其原来目标。

## 原生交互

1. **见面与能力示例**：一句介绍、少量具体成果示例，明确示例不是用户已有资料。小熊使用现有动画和静态兜底。可以开始或先进入产品。
2. **日常情况**：上班、在读、自由职业、经营事业、照顾家人；可以多选，最多3项，全部可跳。只用于理解表达背景，不据此推断收入、人格、作息或权限。
3. **常用应用**：选择熟悉的应用图标。点选本身不授权，只影响下一步适合呈现的资料入口。
4. **兴趣与表达**：可选最多5个主题，并通过短小样例选择信息详略与语气。两个表达维度分开，不要求选择抽象性格标签；跳过保持未指定，不伪装为用户已确认偏好。主题是初始内容偏好，不等于职业或长期目标；已有独立简报偏好优先。
5. **带上资料**：首版呈现已实现的系统日历/提醒事项，以及适用时的飞书连接状态。只有服务已准备好授权时才出现授权动作。下一阶段按常用应用提供真机登录和选定资料导入，须先完成各自验收再开放入口。分支说明数据用途、范围和真实状态。外跳前保存进度，回来继续原步骤。
6. **确认并进入**：显示用户自己的选择和真实来源状态，可以回改。点击完成才将选择用于后续回答。进入现有今天/聊天页面，并保留可再次修改的入口。

流程按日常、应用、兴趣与表达、资料四类组织，主按钮位置稳定，触控区域至少44pt；支持大字、屏幕阅读和减弱动态。兴趣与表达屏包含多项可选设置，需要在用户测试中特别观察停留与退出；较长的原生来源管理属于可选分支，不强迫所有用户阅读。

首版不把换装作为信息采集步骤；衣橱保持在已有个性化入口。选择一种外观不能换取数据访问，也不能影响完成引导的资格。

## 上下文契约

首版仅保存明确点选的有限枚举。角色、常用应用和兴趣支持多选；结果详略和语气可以为空。来源固定为self_selected，有形成/确认时间，账户与身份共同隔离。

- 草稿用于恢复进度，不进入Agent上下文。
- 完成后的点选作为初始偏好进入当前任务所属账户/身份的上下文，不能扩大工具权限或替代动作授权。
- 已有用户修改已完成画像时，编辑草稿留在本机；最终保存成功前，上一版已确认设置仍有效。
- 保存采用revision比较及request_key回执，未知结果先恢复原请求，冲突不自动覆盖另一端修改。
- 跳过首次引导不生成默认画像；清空已完成设置应明确保存空值，不能假装成一次新注册。
- 默认回复行为由产品决定，不记录为用户明确选择。
- 已有手动简报设置优先；只有未单独配置时使用已确认的首登兴趣作为初始候选。
- 导出包含用户可读的当前选择和进度；删除账户覆盖新增表及本机草稿。内部请求回执不当作画像内容导出。

接口精确定义和实现证据以本轮 `onboarding` 契约文档为准。首版不从一个日程、一次内容点击或设备权限推断人格、长期关系或持续执行授权。

## 数据连接与首屏价值

已有原生同步路径读取过去7天至未来30天的日历范围，提醒事项每列表最多500条；只同步用户选择的列表。权限允许但没有列表、列表为空、同步失败、部分读取等都保持各自状态，不统一显示“已了解你”。

有已保存安排时，“今天”展示真实安排；只有兴趣偏好时，后续简报生成使用主题，生成必须走现有明确操作。首登保存本身不启动付费模型、后台任务、通知、定时任务或外部写操作。

未配置飞书、邮箱等外部服务的环境依然可以完成引导。邮箱授权码、企业安装审核和尚未获批的平台scope列入独立连接工作，不用伪按钮占据首次流程。

## 验收

工程与原生验收：

- 新空账户进入、旧账户不被打断、设置重开、返回/跳过、重启恢复。
- 账户/身份切换时旧请求不更新新页面；注销冻结后不得发送新保存。
- 草稿与完成态分离；重复请求、超时回执、409冲突、晚到快照处理。
- 完成偏好真实进入正确任务的模型上下文，其他owner不可见；独立简报设置不被覆写。
- 未配置来源不显示可用；打开来源选择不等于启用，启用不等于已读取。
- 完全无授权、拒绝授权、空数据均可进入产品。
- iPhone原生浅色/深色可读，屏幕阅读标签与点选状态正确；返回连接后恢复步骤。
- App测试、TypeScript和lint；后端身份隔离、生命周期和回执测试；不沿用旧测试计数宣称本轮通过。

用户验证计划（尚未执行）：以相同时间预算比较“事实点选”和“事实点选＋一个相关连接”。记录引导耗时分布、各屏退出率、来源确有内容的比例、首屏有效行动、第一次任务补问次数和画像纠正率。90秒仅是起始设计预算，不作为市场验证结论。

### 首轮观察办法

先招募 6–8 位并未参与设计的人做有主持的形成性测试，覆盖以微信为主、常用办公协作应用、较少记录日程三种情况。这一规模用于发现问题，不能估算市场完成率或留存。每人最多 15 分钟，先自行完成流程，主持人不解释选项；再让其尝试一件自己确实要做的小事。遇到登录、授权或个人资料时由参与者自行操作，观察记录只保留步骤和问题，不收录密码、聊天正文或日历详情。

需要检验三个假设：

1. **选择比描述容易。** 记录每屏首次动作时间、回退、求助、漏看与退出。特别观察兴趣与表达合并的一屏；如果被当成必填或反复犹豫，应减项或延后，不靠解释文案再延长流程。
2. **相关连接能带来可见价值。** 区分“允许了权限”“实际有可用资料”“在今天看到了有用安排”。对没有日历或办公应用资料的人，核对其是否仍能顺利进入并理解产品；不能把授权率当作价值。
3. **选择确实改善第一次使用。** 观察进入产品后是否知道下一步、首个任务需要补问什么、回答是否适配而不刻板。每个画像字段都要能说明对服务产生的具体作用；反复无贡献的字段删除或移到后续使用时再问。

访谈最后让参与者用自己的话说明“Pajio 现在知道什么、连接了什么、接下来会不会自己执行”。若把常用应用点选当成读取聊天历史、把保存兴趣当成自动启动任务，属于理解失败，应优先修正文案或交互，再安排扩大测试。

首次试用不以是否走完全流程判定成功：主动跳过后完成一件有价值的事，同样是成功路径。后续小规模外测再看次日/一周是否主动回来使用，区分真实内容价值与提醒带来的打开；没有这一证据前，不宣称引导能提升留存。
