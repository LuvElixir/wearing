# Pajio 统一开发与验收顺序

2026-10-10。用户最新决定：ZCode 只完成正在执行的任务；后续 App、网页、桌面与共享服务均由 Codex 负责。先完成可用的功能链路，再逐一推进客户端。这一决定取代此前 Web/Desktop 交由 ZCode 的分工；旧交接文档保留为历史证据。

## 功能验收原则

每项功能都按“用户入口 → 真实鉴权 → 所属服务/设备执行 → 回执/产物 → 失败恢复”验收。代码、测试构建、服务部署与客户端实际通过分别记录。没有真实结果的按钮不能显示成功；需要第三方登录、分发资格或实际经过时间的项目单独列出，不以模拟通过替代。

## 功能完成后的客户端顺序

1. **iPhone**：以主要用户端为先，完成登录/引导、任务/结果、远控、文件、记忆、通知与升级的实体机闭环。Apple Developer/TestFlight 资格是分发条件；当前模拟器包不代替分发包。
2. **Android**：复用同一业务与权限合同，验收安装、系统返回/键盘、后台恢复、文件与通知；当前测试签名 APK 不冒充正式发行包。
3. **网页**：同一账户、能力状态、结果和安全交还合同；完成浏览器兼容、移动宽度和网络恢复。
4. **桌面**：在网页能力之上验收原生登录跳转、窗口与输入、文件入口、更新/打包。macOS 与 Windows 分别有真实证据才记完成。

各端可以共享业务逻辑，不能共享未经核实的“已通过”结论。最终按各端功能矩阵逐项关闭缺口，避免仅以构建成功或按钮存在判定完成。

## 后续核心功能优先级

本次源码复核确认，以下三项还没有完成，不能被现有远控能力或 OAuth 接入替代：

1. **P0：注销时的完整资源退出。** 当前 `account_deletion_cli.py` / `account_deletion_operator.py` 的实际供应商适配是腾讯云 CVM、磁盘、快照；`cloud/account_deletion_tenant.py` 撤销设备权限，但未完成 Proxmox 专属电脑、手机登录态及异机归档的清理。先补所有权绑定的资源/备份清单和删除适配、持久操作回执、未知结果对账，再对独立可丢弃测试资源演练。不得拿当前 A/B 的已登录设备试删，不能仅撤权就宣称账号数据全部删除。
2. **P1：资料到可核对的个人上下文。** 已有选择式引导、飞书连接、用户确认后的聊天导入与记忆编辑；缺的是“选定资料 → 带来源的候选事实 → 用户确认/纠正 → 已有记忆系统 → 撤销来源同步失效”。先用合成的聊天导入批次完成，区分本人、第三人、引用与推测，避免为了首轮价值等待每个社交平台都接通。
3. **P1：Agent 可用但不可见的登录凭据。** 当前私密人工远控不等于密码管理器。先对自有合成 HTTPS 登录页实现一个受设备、所有者、origin、页面身份、会话版本约束的原生填充通道；模型只请求登录和读取固定结果，不获得密码或任意选择器。导航变化、撤权、崩溃、未知回执及清理失败必须保留暂停，不自动重放。

自动证书轮换、容量/预算约束的供应、空闲停启和可验证恢复继续属于公开运行条件。以上排序不代表这些条件已经完成。
