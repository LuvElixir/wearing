# Pajio 动效方案与制作清单

2026-10-09。目标：操作有回应、状态有来由、页面有连续性，小熊让人感到被照顾。动效完成时间不影响操作可用时间。本文是本轮审查与实施方案；并非已完成全部接入的声明。

## 1. 先补什么

首轮把资源集中在六件事：**语音手感、任务接收与结果到达、页面与抽屉连续性、连接/导入反馈、八套睡衣统一换装、小熊短回应。**

用原生代码实现按压、手势、页面、列表、输入、进度及状态反馈；WorkBuddy 制作角色表演母片。小熊不承载唯一的状态信息，真实状态始终有文字和可操作入口。

## 2. 本轮发现的现状

依据：2026-10-09 当前源码、素材尺寸/时长检查、视频接触表，以及 iPhone Air 模拟器衣橱现场操作。模拟器当前连接不可用，因此没有用本轮操作验证在线任务动效，也没有进行真机帧率、触感、发热测试。

| 现状 | 影响 | 决策 |
|---|---|---|
| 通用按压为 110ms/180ms，抽屉支持拖拽回位，底栏、语音模式、日期选择已有动画 | 有可复用基础 | 统一使用已有组件，优先补正式业务页缺口 |
| 正式 App 的多处页面直接替换，独立体验预览里的转场未全部接入 | 预览好看不等于用户实际体验一致 | 在正式页面逐条验收，保留聊天 WebView、草稿和滚动位置 |
| 雾蓝小熊每 23 秒播放一段约 5 秒招呼，其他七套静止 | 阅读时可能反复招手；换了衣服就失去动感 | 改为低频在场感；用户事件触发短回应；扩款前固定角色基准 |
| 蓝↔奶油使用 2.875 秒视频，其他服装约 480ms 幕布 | 同一操作等待感不一致 | 所有服装共用一个换衣规则 |
| 原图按边界配准，视频仍有构图差异；视频为不透明白底 | 转换可能露出脸型、大小和底色跳变 | 统一眼位/头高/脚底/相机；日夜背景分别检查 |
| 衣名立即变更，但小熊可能还显示上一套 | 所见与状态短暂矛盾 | 拆开请求、展示、保存三个状态，名称跟随展示提交 |
| 未发现触觉反馈接入 | 录音等关键操作少一层确认 | 少量使用系统语义触感；安卓允许降级无触感 |

源码入口：`clients/mobile/src/experience/primitives.tsx`、`IntentComposer.tsx`、`Mobile.tsx`、`Conversation.tsx`、`TaskDetailPanel.tsx`、`ChatImportPanel.tsx`、`LivingPajamaBear.tsx`、`WardrobeStage.tsx`、`WardrobeFilm.tsx`、`bear-registration.ts`。

## 3. 完整交互清单

下面时长是 Pajio 的第一轮调试目标，需真机调整，不是平台强制标准。P0 为外测前优先打磨；P1 为第二批；P2 为有证据再投入。

| 优先级 / 场景 | 用户看到、感到什么 | 触发与取消 | 实现 / 初始时长 |
|---|---|---|---|
| P0 按压与选择 | 按下轻收，松开回位；选中勾选和底板跟随 | 接触立即反馈，滑出取消；禁用态不假响应 | 原生，沿用 110/180ms；不逐个按钮震动 |
| P0 页面、返回、抽屉 | 层级方向明确；抽屉跟手，半途松手可回位 | 不锁下一次操作；返回保留草稿/滚动 | 原生，约 200–300ms；Tab 不做整页飞行 |
| P0 键盘与输入栏 | 输入栏随系统键盘到位，语音/文本入口自然互换 | 尊重键盘真实高度、安全区与交互返回 | 跟随系统键盘；模式约 140–180ms |
| P0 录音与转写 | 录音开始有清楚确认，上滑取消有阈值反馈，识别文字稳定落入草稿 | 实际录音开始后显示录音；中断/权限失败有明确状态 | 原生 + 可选短“认真听”；真实音量才驱动波形；约 140–200ms |
| P0 消息发送/任务接收 | 发送中留在原位置；确认收到后进入任务状态 | 服务端接受后才出现“已接下”；失败可重试且不重复创建 | 原生状态 + 小熊一次点头；文字反馈约 160–220ms |
| P0 执行进展 | 同一任务卡原位更新，过程可展开，返回后仍找到原任务 | 按真实阶段，不编造百分比；长期执行保持安静 | 原生短过渡约 160–220ms；不持续播放忙碌表演 |
| P0 结果送达 | 新结果在原卡出现，短暂强调可打开的位置 | 结果确实可用后出现；阅读旧消息时不强拉到底 | 原生约 180–240ms + 可选一次递卡；无需看完才能打开 |
| P0 等待决定/出错/重连 | 状态停稳、原因和下一步清楚；错误保留输入和重试位置 | 无震屏、无委屈小熊；恢复后在原位置更新 | 原生，短淡化；不反复弹提示 |
| P0 连接、授权、导入、同步 | 在同一卡片中呈现真实阶段与成功标记 | 区分已授权、已连接、读取中、已导入、候选理解；拒绝可返回 | 原生约 160–220ms；无数据时明确空状态 |
| P0 八套换衣 | 选择立即响应，角色以统一动作完成换装；保存另有确认 | 快速点选合并到最后一次；加载失败保留原穿搭；退出取消表演 | 原生遮挡约 500–800ms，整理袖口可选约 1s；不锁交互 |
| P1 初次引导 | 点选轻落位，进度前进，已选择的信息收成可修改摘要 | 不要求开场打字；可跳过/回退；连接成功不等于已理解 | 原生约 160–220ms；完成一次轻点头，无强制开场片 |
| P1 记忆与资料 | 资料进入对应位置，展开/收起保持来源关系 | 写入完成才显示已保存；推断需用户确认；删除有清楚反馈 | 原生约 180–240ms；资料不无意义飞向小熊 |
| P1 今天简报 | 卡片就位，展开保留上下文；新内容有轻提示 | 有真实内容才展示；不用逐字慢放；不自动翻页 | 原生约 160–220ms |
| P1 搜索与筛选 | 结果温和替换，保留输入焦点和选项位置 | 请求过期不闪回；加载与无结果区分 | 原生短淡化；避免每敲一字就列表大幅移位 |
| P1 远程手机/密码授权 | 接管、控制权交接、锁定有明确回执 | 已停止 Agent/已获得控制权后才显示成功；敏感输入阶段保持画面稳定 | 原生状态，不用表演代替真实控制权或解锁状态 |
| P1 日夜外观 | 背景和表面柔和切换，文字全程可读 | 用户主动切换可短过渡，跟随系统尽量安静 | 原生颜色过渡约 180–240ms；视频底色另验收 |
| P2 空闲、欢迎、晚安 | 首次见面一次小招呼，长期阅读保持静止；晚安可安定坐下 | 用户主动进入角色页/休息模式；不暗示任务已经停止 | 稀疏短角色片；默认无声音、无持续漂浮背景 |

## 4. 小熊动作库：先少而精

| 动作 ID | 场景与表演 | 播放规则 | 制作次序 |
|---|---|---|---|
| B01 quiet | 自然眨眼、微呼吸，身体稳定 | 稀疏，阅读不反复招手；循环必须检查接缝 | 第一批后补，替代招呼充当待机 |
| B02 listen | 手爪放下、轻倾头、目光稳定 | 录音真正开始时一次；音量反馈由 UI 表达 | 本轮 WorkBuddy 试片 1 |
| B03 received | 轻点头一次、小幅收爪，安定下来 | 服务端接受交代后一次；可立即打断 | 本轮 WorkBuddy 试片 2 |
| B04 result | 从口袋取出空白卡片，轻轻递来 | 真实结果到达，且当前界面允许时一次 | 本轮 WorkBuddy 试片 3，手/卡稳定为验收重点 |
| B05 dress | 进入遮挡、换装、出来整理袖口 | 只在衣橱，由用户选择触发 | 统一方案先做一套试片，再扩八套 |
| B06 welcome | 一次小招手，回到平静姿态 | 初见/主动互动；不定时循环招手 | 现有雾蓝片可重新裁切评估 |
| B07 goodnight | 慢慢安定坐下，短呼吸，静止 | 用户主动休息时；执行中的任务仍独立显示 | 第二批，优先级低于主操作反馈 |

先生成雾蓝版本评估脸型、动作、构图，再复制同一规范到其他睡衣。不能用蓝色动画覆盖用户已选的另一套睡衣；对应动作未齐时使用正确服装的静态姿态。不制作“出错哭泣”“催用户点头”“鼓励多授权”的情绪施压动作。

## 5. 换衣的可扩展实现

统一角色站位、眼位、头部宽度和脚底线。**通用原生遮挡 + 每套服装的进入/出现母片**：八条母片可拆成最多十六个进出片段，不做五十六个服装配对。遮挡完全关闭时更换角色/衣名；整理衣领等表演放在出现之后，随时可继续操作。

状态明确为 `requestedOutfit`（想试的）、`displayedOutfit`（实际展示）、`savedOutfit`（已保存）。连点采用最后请求优先；在遮挡尚未关闭前可更新目标，已出现后从当前展示态开始下一次切换。不排队表演。保存按钮的对象要与当下明确显示的衣服一致，失败不误报穿上成功。

原生快速过渡是所有八套的共同底线。若生成视频无法保证相同熊体/相机，就保留原生方案，暂不接入失真的片段。长期需要真正连续换衣时，再考虑同一骨架与服装层的角色资产；当前生成视频不等于已有实时换衣模型。

## 6. 全局动效规则

- 同一时刻只突出一处信息。熊点头时不同时让背景、按钮、整张卡都弹跳。
- 结果先可用，表演随后可选。点击、返回、连续换衣都能打断动画。
- 缩放轻微，避免全屏弹簧、反复上下漂浮、内容逐字慢显、假进度、每个按钮震动。
- 声音默认关闭；触感只用于明确事件，采用平台语义。录音期间避免触感污染采音。
- 减少动态效果启用时角色视频停播；空间移动降为淡化或直接更新，保留全部文字、状态和功能。
- 视频离屏/切后台/页面失焦暂停；一个主表演解码器优先；首帧未到、解码失败时使用同构图静态图。登录、保存、发送不依赖视频下载。
- 日夜两套场景验收，不透明白底片不得直接铺在深色界面冒充透明角色。
- 当前八张 1254px RGBA 图片常驻解码体量粗算约 48MiB，尚非实测。列表缩略图与主角色应分别提供合适尺寸，测量后再调整缓存。

## 7. WorkBuddy 制作与验收

制作包：[`BRIEF.md`](../../design/motion/pajio-20261009/workbuddy/BRIEF.md)。范围仅制作目录和拷贝的角色图；用户已授权使用剩余积分，本轮先三条候选，质量通过后才扩款。可使用完现有积分；不新增购买或订阅。

交付保留源片、提示词、实际生成记录、分辨率/帧率/时长、可获得的任务ID和积分信息。源片约 4–6 秒供选取动作，App 中一次回应通常更短；不靠粗暴倍速压缩表演。MP4 白底不是透明视频；部署格式等画质、抠像与性能试验后确定。

每片检查：身份/嘴/眼距、肢体和睡衣稳定；固定机位；前后静止帧；脸和脚底不漂；动作读得懂；无文字/声音/多余道具；接入后的前后衔接。生成器自称完成不算验收。候选片先保留在制作目录，未经现场播放与日夜背景检查不进入生产资源。

## 8. 如何判断有用

先用一轮 6–8 人探索测试检查主要问题，不将其当作市场已验证结论。让用户连续试衣、录音取消重录、授权后返回、等待一个真实任务结果。原版与候选版顺序对调，记录：重复点击、误触、完成时间、动画打断成功率，以及“轻快/舒适/被打扰”主观评分。

工程验收使用 Release：iPhone 真机 + 较慢 Android；同时滚动、录音、图片加载时看慢帧。60Hz 以约16.7ms帧预算为参考，不把模拟器观感当实测。记录首帧等待、启动耗时、内存峰值、后台播放停止、无网回退、减少动态和系统大字可用性。持续使用十分钟是否疲劳，比单段片好不好看更重要。

首轮交付顺序：统一动效与状态控制 → 语音/导航/任务/导入 P0 → 八套换衣规则 → 三条熊片质量试验 → 少量现场用户测试 → 再扩款及晚安。

App 由 Codex 完成；Web/Desktop 由 ZCode 对齐已验收的 App 状态和设计规范。聊天主体当前为共享 WebView，消息布局与列表动画需同 ZCode 协调；不能靠 App 外层移动掩盖内部跳变。

## 官方依据

本轮制作结果和独立审阅见 [候选审阅记录](../../design/motion/pajio-20261009/REVIEW.md)。WorkBuddy 已完成三条源片，界面显示消耗 353.93 积分；当前均为候选，尚未接入 App。

- [Apple Motion](https://developer.apple.com/design/human-interface-guidelines/motion)：反馈、空间关系、简短可中断；高频使用要克制。
- [Apple Playing haptics](https://developer.apple.com/design/human-interface-guidelines/playing-haptics)：触感与事件同步，语义一致，控制频率。
- [Apple Reduced Motion evaluation criteria](https://developer.apple.com/help/app-store-connect/manage-app-accessibility/reduced-motion-evaluation-criteria)：降低装饰运动，同时保留状态信息和功能。
- [Android Haptics design principles](https://developer.android.com/develop/ui/views/haptics/haptics-principles)：按平台能力设计触感及降级。
- [Android Slow rendering](https://developer.android.com/topic/performance/issues/render)：按刷新率和真实设备测慢帧，不能仅凭视频观感验收性能。
