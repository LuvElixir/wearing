# Pajio 国内上下文来源与真机连接方案

2026-10-09。状态：公开资料研究、代码审计与开发方案；**不代表这些第三方平台已经在 Pajio 中接通或实测**。后续选定聊天导入与设备接管权限基础的实现进展见[本轮验收记录](../evidence/pajio-context-20261009/acceptance.md)。本文修正首轮新手引导方案中过度依赖公开 API 的判断，补入本人登录的物理真机、原生分享和官方导出三类来源。

## 1. 决策

Pajio 的连接层应支持三条并列路线：

1. **真机上的应用**：本人远程接管固定归属的物理手机完成登录；Agent 在获准范围内读取真实 App 的本人可见页面。没有公开收藏 API，不等于无法读取本人收藏页面。
2. **官方结构化连接**：飞书、日历、邮箱等在条件具备时使用原生权限、OAuth、API 或邮件协议，减少逐屏操作和持续同步成本。CLI 是调用工具的一种包装，不是平台必须具备的条件。
3. **用户选定的资料**：微信聊天转发、应用数据副本、链接、截图和文件。一次导入可以独立产生价值，无需先建立持续连接。

用户主要用 iPhone，与执行端采用固定 Android 真机并不冲突。执行设备可使用用户自有闲置手机，也可采用用户独占的托管手机。不能把多用户轮流登录同一 Android 主用户当成已隔离的托管方案。

“应用账号登录”“允许读取哪些资料”“允许持续刷新”“允许执行外部动作”分别管理。首次引导只要建立一个有用来源即可，不强迫一次完成全部应用登录。

## 2. 微信的新变化：可确认与待验收

**微信选定聊天记录转发到第三方应用，应进入正式接入范围。** 腾讯 WorkBuddy 官方更新日志在 5.5.0（2026-09-01）记载了通过 macOS、Windows 系统分享入口接收微信聊天记录的能力。[腾讯官方日志](https://www.codebuddy.cn/docs/workbuddy/Changelog)

WeChatBridge 的一级实现资料描述了 Mac 微信 4.1.13 起的“多选 → 合并转发 → 转发到其他应用”路径。其接收扩展通过系统文件接口取得 ZIP，解析聊天 TXT 和可用附件；无需为了这条路线引入数据库解密。[实现说明](https://github.com/freestylefly/WeChatBridge/blob/main/README.md) · [归档解析源码](https://github.com/freestylefly/WeChatBridge/blob/0b00e3f89ace0e8f5d9c17478b2c966d0e2b890e/macos/Sources/WeChatBridgeCore/WeChatNativeArchive.swift)

证据边界：腾讯官方日志确认接收产品已支持；WeChatBridge 是独立开发者的实现，不能当作腾讯对所有版本的兼容承诺。本机只读版本检查为 Mac 微信 4.1.13（269631）；本轮没有打开聊天、转发或导入真实记录。

手机版 8.0.78 的同类能力已有非官方实测报道，但微信官方 iOS 版本历史未明确列出该功能。iPhone/Android 的入口、灰度、载荷与数量限制需要分别验收。不能把桌面端证据直接扩大到所有手机。[官方版本历史](https://apps.apple.com/cn/app/%E5%BE%AE%E4%BF%A1/id414478124) · [非官方手机实测](https://www.chaincatcher.com/article/2290109)

这与微信迁移、电脑备份、个人信息副本、企业微信会话存档不是同一能力。选定片段分享不提供全账号历史的持续读取权，也不能默认当前会话中的每个人都同意被建立画像。

产品入口建议为 **“导入选定聊天”**：显示适配当前端的操作指引，接受系统分享或用户选定文件，先预览再导入。允许用户明确哪些发言是自己的；无法确定时只保存原始来源角色，不猜测。群里他人的计划、转述和引用不得直接变成用户的个人事实。

## 4. 新手引导如何接入

现有点选引导继续作为可跳过的基础；将后续“带上资料”扩展为与常用应用匹配的连接分支：

1. 用户只选择平时使用的应用，不要求先描述目标。可跳过。
2. 展示一个最相关、已经实际支持的来源，以及能产生的具体结果，例如“整理所选收藏夹里的内容”，而非“完善你的画像”。其他来源放“稍后连接”。
3. 对真机来源提供 **“打开手机，我来登录”**，进入私密人工接管。对微信提供 **“导入选定聊天”**；有官方授权的应用提供登录确认。
4. 登录后用户点选资料范围；首轮给一个小范围默认建议，用户可缩小或取消。初始采样可试验一个收藏夹或最近 20 项，但这是待测参数，不代表各平台实际支持或目标必达。
5. 数据处理移到进入产品后继续；先回报实际取得的内容及来源，再呈现少量可确认、可修改的发现。超时或资料为空不堵住产品入口。
6. 需要持续刷新时，再让用户选择频率和范围。首次连接不自动开启推送、定时执行或付费后台任务。

授权越多不等于理解越准确。结果验收关注：得到一条可用事实需要的时间、来源有内容的比例、用户纠正率、第一次服务减少了什么重复说明。不能把预设人群标签、MBTI 或模型猜测当作真实理解的证明。

## 5. 上下文的数据合同

建议新增来源记录，至少区分：

- 连接：owner/identity、平台、路线、设备、可核对账号、当前权限、有效状态。
- 范围：数据类别、选定列表、时间/数量上限、用途、一次性或刷新；其版本与批准时间。
- 事实证据：原始内容或受限引用、原作者、平台记录标识、原发生时间与采集时间、来源定位、内容哈希、完整/截断状态。
- 候选理解：基于哪些证据、推断内容、时效与不确定性；明确区分事实和推断。不由频率高就自动赋予高置信度。
- 用户记忆：用户确认/修正结果、版本与来源依赖。使用在回答里的事实也要能追溯，不只长期记忆有来源。

账号切换使旧读取授权失效；不把新账号继承成同一个人的来源。所有查询、导入、缓存、任务及撤销均以 owner/identity 约束。

原始聊天、帖子和文档内容属于外部资料，即便写着“忽略规则/执行命令”也不能改变工具权限。由内容提到一个人、疾病或政治主题，不自动推断用户身份、健康、政治观点等敏感特征。

断开连接停止新读取。2026-10-09 微信选定聊天首版后端只接收用户在设备上预览确认后的规范化文本和附件声明，不上传原 ZIP、不下载附件，也不自动建立任务、候选理解或长期人格。删除批次会清空该批原始规范化正文、附件声明与检索索引，保留不含正文的删除回执以阻止网络重试恢复已删除内容；删除前要求当前任务结束或确认停止，并重置后续对话会话。已经生成的回答、用户另行保存的记忆、历史会话和此前下载的导出包仍保留，不能把“删除来源”宣传成这些衍生内容也已删除。原文件仍在用户自己的设备上。

未来若引入自动候选理解或衍生记忆，必须建立来源依赖并支持连带清理，保留其他独立来源仍能支持的记录，验收后才能承诺完整来源撤销。现有私有租户注销会覆盖数据库、索引与备份的整体删除；共享租户成员注销仍因归属登记不完整而阻断，不能对外声称其已支持完整清除。第一版代码与合成测试不是 iPhone/Android 微信原生分享兼容性的真机验收。

## 6. 真机远程接入是基础能力

目标链路：**用户的 iPhone/Android Pajio → 认证的远程会话 → 设备所在电脑连接器 → USB 物理 Android**。详细审计、所有权状态机、私密登录和验收见[物理真机接入合同](pajio-physical-device-access-2026-10-09.md)。

现有 Agent 已有真机动作与私有 relay；App 有配对、权限、暂停/恢复管理。**用户实时视频、人工触控、私密键盘输入与完整接管尚未实现。** 原有云端动作账本保存参数，不能直接拿来传用户密码。

私密登录须在设备网关层暂停所有 Agent 观察/输入及旁路采集；人工输入不进入模型、工具参数日志或录屏。断连保持暂停，不能自动交回 Agent。远程画面、点击和输入绑定同一租户、设备、会话和 epoch；不能开放公网 ADB。主机和设备操作系统仍是可信边界，不作“任何参与方都无法接触密码”的绝对承诺。

读取 UI 也可能产生浏览、播放、已读或推荐信号；“只读资料”描述的是任务意图，不代表平台零副作用。各平台必须验收登录共存、主手机是否被退出、验证挑战、分页、重启后登录态、账号切换、读取副作用和撤销清理。真机可降低某些环境差异，不能保证没有平台登录限制。

## 7. 开发顺序与交付门槛

| 工作包 | 交付内容 | 才能宣称完成的证据 |
|---|---|---|
| A 微信选定资料导入 | App 系统分享/文件接收、归档本地预览、范围确认、消息来源、批次撤销 | 无隐私测试会话的 iPhone/Android 实际分享或文件导入；真实格式覆盖与失败恢复 |
| B 真机人工接管 | 统一设备网关、视频、触控/中文输入、独占租约、私密登录、断连恢复 | 实际 iPhone 控制 Android，合成秘密不进入日志/模型；2 用户×2设备隔离；跨网络与重启矩阵 |
| C 平台适配试点 | 小红书、B站、抖音分别定义可见资料和采样范围；飞书结构化路线并行 | 各自真实账号由本人登录；选定类别可复现读取、有来源回执、无越界动作；平台逐项报告 |
| D 上下文与首屏价值 | 证据/候选/记忆分层、来源撤销、返回结果卡、引导分支 | 真实用户理解与修正测试；拒绝所有连接仍可用；失败不阻断首登 |
| E 扩展来源 | 微信读书、豆瓣、邮箱和其余候选逐项接入 | 同样按平台验收，不因一个列表页成功而显示整账号已接通 |

A 与 B 可独立推进。C 的真机分支依赖 B 的完整人工接管与隐私验收，不能只因 Agent 之前能点击手机就跳过。飞书、系统来源与分享路径无需等全部真机平台完成。

归档导入必须限制压缩体积、解压总量/条目数/压缩比，拒绝路径穿越、符号链接和不支持的嵌套包；格式/MIME、编码、重复文件、损坏 ZIP、附件缺失均要测试。预览不执行 HTML/脚本，不把文件名作为可写路径。现有分享限制为 4 文件、每文件15MiB、总30MiB，支持图片/PDF/文本等，**不能据此宣称已支持微信 ZIP**。新归档限制需要通过格式样本与性能测量确定，不直接放开原有限制。

Codex 负责 App 与共享后端、协议和真机执行；Web/Desktop 仍交 ZCode，后者只读 App 代码，以已验收协议实现遥控入口及 Mac/Windows 分享接收。没有端到端证据前，连接卡使用“待本人登录/已登录/可读取哪些范围/读取中/取得部分资料/失败”等真实状态，不使用一个泛化的“已连接”掩盖差异。
