# 产品验证执行包

版本：2026-10-07。状态：研究材料已准备；尚未招募、发送邀请或收集外部用户数据。没有虚构访谈结论。对应[完整方案](./product-brand-ux-strategy-2026-10-07.md)。

## 1. 问题访谈：12 人，先看过去的行为

招募首批相似群体：中文项目负责人/独立顾问中，过去一周做过至少三次资料整理或事项跟进的人。先从一个工作场景取样；开发者与创始人最多占三分之一，至少三人不是高频 AI 用户。与创始人有利益关系、员工或朋友身份单独记录，避免只找会夸产品的人。

筛选问题：过去一周具体做了几次；用哪些工具；最近一次结果是什么；花了多久；能否用脱敏材料复现；是否愿意参加 30 分钟访谈。不能把“是否喜欢 AI/小熊/愿意省时间”作为筛选条件。

邀请草稿（未发送）：

> 我们在研究资料整理和事情跟进的工作方式，想了解你最近一次真实经历，包括目前工具哪里已经很好用。访谈约 30 分钟，不需要购买，也不需要提供私人账号。可以用公开或脱敏材料；是否录音由你决定。后续可自愿试用。

访谈顺序：

1. 回到最近一次真实任务：为什么开始，谁需要结果，什么时候算完成？
2. 请按实际顺序讲一遍，最好用脱敏材料演示。哪里花时间，哪里只是等待？
3. 最后一次漏跟进或结果出错是什么？如何发现、补救，代价是什么？
4. 已用什么办法改善？买过什么、停用过什么？为什么？
5. 哪一步愿意让助理做？哪一步必须自己判断？需要看到什么才放心离开？
6. 若只能解决一个重复环节，哪一个值得下周再用？为什么？
7. 最后五分钟才展示产品解释，要求对方复述。不要提前用“睡得不好”“很温暖”引导答案。

记录真实频率、任务输入/输出、现有替代、授权障碍、失败代价和反例。每条结论附匿名参与者编号及原始笔记位置；无依据就保留为假设。

## 2. 两轮可用性：各 5 位，修复后再测

第一轮测试现有问题与新结构的可理解性，第二轮使用未见过版本的人复测。相似目标用户的小轮次适合发现问题，不用来估计市场占比。[方法参考](https://www.nngroup.com/articles/why-you-only-need-to-test-with-5-users/)

统一任务包使用虚构公司与公开资料。开始时说明是在测试产品，操作失败不是参与者的问题。主持人不给按钮提示；卡住 60 秒后可以帮助，但记为“需帮助”。

| 任务 | 提示给参与者 | 观察与通过条件 |
|---|---|---|
| 交代 | 明天要和一家客户沟通，手上有两份材料，请让产品准备一页提纲 | 能找到输入、添加资料、改正转写、主动发送；知道是否已经开始 |
| 离开 | 现在有别的事情，请退出 App，稍后回来 | 不重复发送，不误以为必须盯着；恢复后找到同一任务 |
| 决定 | 产品准备了一封跟进邮件，请查看并决定是否发送 | 能说出收件人、附件和后果；“暂不发送”不会丢掉草稿 |
| 失败 | 第三份资料权限已失效，请处理 | 识别部分完成而非全部失败；知道如何补材料，已有结果还在 |
| 回看 | 一小时前交代的事现在到哪一步了？ | 10 秒内找到正确结果/阻塞，能复述下一步；未完成不说成已完成 |
| 记忆 | 一条旧偏好已不适用，请纠正 | 找到来源与修改入口；知道这次改动影响什么 |

每步记录：成功/需帮助/失败、耗时、错误点击、是否误解状态、关键原话、严重程度。操作之后再问主观舒适和信任，防止偏好回答替代行为结果。核心错误单列：保存=执行、输出=外部完成、已读=批准。

## 3. 品牌、角色与名称的匹配实验

先检验定位再检验角色。两套解释只改变价值表达：A“持续跟进，回来查看结果”；B“晚安，把事情留给助理”。画面、功能、任务保持一致，顺序交叉。问“它能做什么、什么时候会用、何时不会用”，观察睡眠场景是否把全天能力误限缩。

角色测试使用同一流程、同样结果与同样文案：一个版本无角色，一个版本小熊只在头像和欢迎处出现。各参与者顺序交叉；不同时改变颜色、排版、动作与品牌名。指标：用途理解、任务完成、愿意交付哪类数据、回看效率、对能力的错误期待；“可爱程度”仅为补充。

没有角色默认获胜的前设。如果可爱提高识别且不损害用途理解或信任，可以保留更显眼的位置；如果分歧明显，采用可选角色。如果仅受喜欢但不带来真实使用，停止额外资产投入。小样本不宣布显著提升。

名称“余刻”仅为首选研究候选。先进行同名产品与可用性筛查，再测试听写、首次联想、产品解释后复述及次日回忆；不把尚未核验的名字登记成正式品牌或购买域名。

## 4. 任务与语音基准

同一批脱敏资料做 12 个标准任务，每类 4 个：会前准备、资料比较、持续跟进。覆盖信息缺失、来源冲突、过期资料、权限失效。固定成功标准后才执行，保存输入版本与来源时间。

对照为用户目前做法及其现用通用 AI；顺序轮换，避免同一个人重复资料学习导致虚假的提速。执行者记录人工操作与等待，评阅者尽量不看产品名，只评关键事实、来源、完整度、可用程度。无法盲评的项目标明。真实用户资料不随意转发给多个供应商。

语音另做 40 条、每条 5–15 秒、至少 5 位说话者的初始样本：普通中文 10、专名 10、数字日期金额 10、夹英/可控噪声 10。分别报告字符错误率、关键字段正确率、p50/p95 延迟、用户修改耗时。样本规模仅支持发现问题；口音覆盖不足继续补样。

记录手机型号/系统、网络、录音时长、音频格式、服务版本；第一轮锁定当前 Seed-ASR 2.0。只有质量或成本明确不达标时才做受控供应商对比，不把不同网络/不同录音条件造成的差异归因模型。

## 5. 真实任务试用与付费

20 位完成首次任务的用户试用两周，目标至少 60 个符合首批范围的真实委托。另记所有超出范围的请求和被拒需求，不能只挑能成功的任务报告全产品成功率。

可人工协助排障，但必须记下介入类型和时长；用户知道是试验期。人工替做的任务不计入自主完成率。研究提醒带来的使用与用户自行回来分开。

第一周中段只做一次中性回访；第二周尽量不催用。退出者仍计入初始样本，不把流失用户从分母删掉。前 60 个是运营检查点，另按三任务类型展示，防止问答刷高成功率。

付费在服务、账单、取消与退款规则具备后进行。先依据成本确定可持续价格区间，再对不同试用批次测试同一权益的清晰报价；不能对小样本转化率差异过度解释。明确自动续费与额度，真实付款后继续观察使用和续用。报名、口头愿付、点击价格页只算意向。

## 6. 事件与数据最小化

分析默认不记录语音原文、文件正文、私人名称或完整 URL。任务 ID 和匿名用户 ID 隔离，诊断录音/文本需单独同意并设置删除期限。实验参加者可撤回。

| 事件 | 关键字段 | 用途 |
|---|---|---|
| input_started / transcript_ready | input_id、时长、阶段耗时、错误类型 | 输入速度与失败定位 |
| task_submitted / task_admitted | request_id、task_id、任务类别、回执类型 | 发送与真实接收的区别 |
| task_stage_changed | task_id、阶段、观察时间、执行端状态 | 持续推进与停滞 |
| decision_presented / resolved | task_id、动作类别、结果、版本 | 决策负担与安全恢复 |
| artifact_opened / exported | task_id、artifact_id、版本、产物类别 | 结果访问；不自动推断已接受 |
| result_use_reported | 可直接用/小改/大改/无用、原因、研究来源 | 有效交付的明确反馈 |
| task_retried / stopped | task_id、原因、是否产生外部动作 | 可靠性与重复操作 |
| return_summary_opened | 离开时长分桶、结果/待决定数 | 回看路径 |
| cost_recorded | task_id、模型/ASR/执行/存储/重试成本 | 每有效委托成本 |

任务事件按唯一 ID 去重，失败和重试不漏计。留存按首次有效委托的 cohort 计算，而非安装日；另外报告全部入组人数的转化。缺失数据写未知，不能填 0 或成功。

## 7. 决策记录模板

```
问题：
假设：
证据编号 / 参与者与样本范围：
观察到的行为（含反例）：
指标分子 / 分母 / 未评价：
可能的其他解释：
决定：保持 / 修改 / 暂停
修改范围与负责人：
复测时间与通过标准：
```

每周只基于记录决定下一批工作。若创始人意见与用户行为相反，先查样本与任务适配，再做小范围复测；既不把单个用户当全部市场，也不以审美坚持覆盖持续失败的证据。
