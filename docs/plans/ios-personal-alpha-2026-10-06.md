## 先把三个交付分清

| 交付 | 用户能判断什么 | 不能据此声称什么 |

## 用户先体验的页面集合

体验预览是具备状态和返回关系的完整流程，不是只有首页的静态拼图。样例数据标明演示，不写入真实日历、订单或支付记录。保持 Wearing 的既定角色和品牌；吸收参考截图的低负担入口、持续关系与主动信息，不照搬五个等权导航页。

| 页面 / 状态 | 主要问题 | 可直接感受的操作 |
| --- | --- | --- |
| 现在：空闲、已有对话、收到进展 | 此刻有什么值得看、说一句会发生什么 | 默认语音；键盘可快速切换；展开一条主动进展 |
| 语音：未授权、录音、取消、识别、失败、转文字 | 有没有录到、能否反悔、原话是否丢失 | 开始 / 停止 / 取消；识别后修改发送；失败保留原件 |
| 对话与任务进展 | Agent 正在做什么、需要我时怎么办 | 看进展；结束当前执行；收起并回到原位置 |
| 确认卡与决定回执 | 我到底同意什么 | 动作、对象、必要费用 / 影响；一个主按钮；拒绝；过期不可重复提交 |
| 结果：简报、数据、行程、图解 | 能否快速理解、比较、决定 | 阅读层级、操作图表、查看依据、关闭回原任务 |
| 回看：日历、Todo、笔记 | 整理结果是否准确 | 筛选与日期切换、详情、原话 / 原件、纠正、版本冲突；不要求用户重新录入 |
| 持续目标与定时安排 | 哪些事还会继续、何时再来 | 看下一步、暂停 / 继续、调整原目标、查看历史与卡点 |
| Wearing 与记忆 | 它记住了哪些事实、能否纠正 | 查看依据与更新时间、纠正 / 忘记；不以虚构亲密度或无来源的赞美代替记忆 |
| 身份与连接 | 当前谁在行动、资源是否可用 | 切换前保留草稿；列明关联设备及状态；重连；不暴露服务密钥 |
| 设置、权限、离线、重试 | 出问题是否仍可理解与恢复 | 通知偏好、权限拒绝出口、原件留存、待同步、取消重试与反馈 |

## 手感验收契约

以下是待验收标准，尚不代表已达到。先记录 iPhone 型号、iOS 版本、构建号、网络和复现视频，再判断效果。

| 链路 | 必须满足的行为 |
| --- | --- |
| 语音默认 | 打开后可直接找到语音主操作；文字切换一步可达；无自动开麦。主操作至少 44pt 可点击，语义和可读状态明确 |
| 录音取消 | 录制中始终可取消；取消有明确结果且不上传 / 不发送；来电、耳机切换、锁屏、进入后台后不得偷偷持续录制；返回后说明保存或未保存 |
| 语音发送 | 保留原话、识别状态、修改与发送边界；网络慢不伪装完成；对取消或身份已改变的旧请求，不把结果注入新会话 |
| 安全区和键盘 | 灵动岛 / 刘海 / Home Indicator 不遮操作；键盘弹出不叠双层输入器、不挤掉主按钮；中文输入法联想、听写、外接键盘和长文本都可用 |
| 返回与滑动 | 原生边缘返回、关闭结果和下拉关闭 sheet 含义一致；取消手势不退出；回到原滚动位置、输入内容和展开状态；不靠模拟动画掩盖整页重载 |
| 动态 | 手指按下即有反馈，过渡可被打断；不连续串联动画阻塞下一次操作；减少动态时使用稳定替代；触觉只用于有意义的边界与完成 |
| 长任务 | 离开 App 后由服务端继续；返回恢复准确状态；按停止后立即有反馈并显示实际停止过程；后端未停止前不能显示已停 |
| 离线 | 文字与已完成保存的原件可回看；待同步明确；重复点击 / 恢复网络只生成一份；无法联网的动作保留输入；过期确认卡不可离线批准 |
| 通知 | 仅在完成、有意义变化或需要决定时触达；点击落到正确身份与原任务；同一事件去重；已读跨端一致；拒绝授权后 App 内仍可回看 |
| 原生权限 | 相机、麦克风、照片、通知、日历分别在使用时说明并请求；拒绝、系统设置撤销、仅部分照片授权都能恢复，不反复强迫弹窗 |
| 可访问性 | VoiceOver 顺序、按钮名称与状态正确；动态字体不截断关键动作；深色环境下不靠低对比文字表示唯一状态；减少透明度时仍清楚 |
| 信任与恢复 | 测试崩溃重开、跨日、升级、身份切换、请求响应丢失；草稿、确认回执与任务版本可核对；故障可从原位置继续 |

性能基线至少记录冷启动到可表达、录音按下到状态反馈、停止到转写完成、键盘展开、结果展开 / 收起、长列表滚动掉帧和后台回前台恢复。页面预览用于收敛方向，触觉、60/120Hz 流畅度和音频中断必须在真机证明。

## 交付里程碑

### M0 · 用户看完整体验

交付上述页面与状态的可交互预览，支持一条完整路径：说出想法 → Wearing 理解 → 给出结果 / 待确认 → 决定 → 回看原任务。另有离线 / 权限拒绝 / 错误恢复。用户在这里确认方向，而不是等安装 TestFlight 才第一次看到新界面。

完成线：没有无法解释的死按钮；样例与真实能力边界清楚；逐屏能够返回；界面和内容语言统一；主要流程的操作次数、主按钮位置和退出方式稳定。

### M1 · iPhone 原生触感验收

用 Expo 57 匹配开发包验证原生录音、照片、键盘、安全区、返回、状态恢复。准备一个隔离测试身份，不向用户既有日历 / 笔记插入测试内容。对话输入与路由优先原生化；复杂生成结果继续隔离 WebView，并由原生容器管理关闭、失败与分享。

完成线：同一真实 iPhone 的核心手感矩阵通过；每个未通过项记录为缺口；保留构建号与屏幕录制证据。Expo Go 可用于已有模块的早期核查，不能替代最终配置和签名包。

### M2 · 能离开电脑使用的私人 alpha

提供可达 HTTPS 地址、真实登录与设备凭据、稳定 Agent 进程、数据备份与恢复；媒体请求和转写不依赖一条仅本机可见的 URL。添加通知原子事件、设备 token 绑定 / 撤销、去重和深链接，先在个人账号单设备走通。Expo 通知能力支持取 token、接收和处理点击，但服务端发送、业务去重、路由与回执仍要由 Wearing 实现。[Expo Notifications](https://docs.expo.dev/versions/v57.0.0/sdk/notifications/)

完成线：Wi-Fi / 蜂窝切换后仍可用；App 关闭后目标由服务器推进；通知返回原上下文；离线内容恢复只同步一份。云资源费用在实际恢复或新建前核实。

### M3 · TestFlight 安装与一周日用

核实 Apple Developer 团队与 Expo 项目归属后，生成商店签名 IPA，上传到 App Store Connect，等待处理并配置合适测试组。上传和处理完成不等于已经交付到用户手机；保留实际安装、登录、重开与升级验证。TestFlight 可收集截图反馈与崩溃反馈；内部测试和外部测试的资格及审核要求按实际账号选择。[Expo iOS 提交](https://docs.expo.dev/submit/ios/)、[Apple TestFlight](https://developer.apple.com/testflight/)

连续一周观察：用户是否自然打开、多少意图一次理解、多少事情被真正推进、多少次重复确认 / 重说、无意义打扰和丢失输入。功能数量不替代这些指标。每日少量真实任务即可，不让用户承担写测试报告的工作。

## 构建配置使用边界

`clients/mobile/eas.json` 是本轮准备的构建意图，未运行构建。没有写入 Apple Team ID、App Store Connect App ID、Expo project ID、签名材料或服务密钥，也没有启用自动提交。保留已有 bundleIdentifier，正式归属待核查。

后续工程顺序：先安装 SDK 匹配的开发客户端、完成 lint / typecheck / 核心测试和资源导出；再登录选定 Expo 项目、核对 Apple 团队，明确服务地址与构建号；开发包验收通过才准备商店签名版本。项目使用 npm，所以 EAS 命令采用 `npx eas-cli@latest ...`，不运行未安装的旧全局命令。

内部 ad hoc `preview` 需要目标设备包含在签名许可列表；TestFlight `production` 则走 App Store Connect 测试分发。不得把 ad hoc 下载链接当作 TestFlight 邀请。[Expo 内部分发](https://docs.expo.dev/build/internal-distribution/)

## 能力边界

iPhone 首先是 Wearing 的表达、拍摄、通知、回看与决策入口。系统照片、日历、提醒、分享等通过各自允许的原生接口接入。当前方案不承诺在普通 iOS 上任意读取或操作微信、支付宝等其他 App；手机自动执行仍通过具备权限的 Android / Mac 等连接器完成。Agent 常驻核心与服务器任务不应依赖 iPhone 的后台存活时间。

### Apple 账户登录阻塞 · 2026-10-06

用户在 D-U-N-S 查询的 Apple 登录页遇到「你的 Apple ID 暂时不符合使用此应用程序的条件」，已从实际页面核对。此时公司信息尚未提交，所以不能认定公司审核不通过。官方资料未给该报错提供唯一原因；不能断言是手机号登录、未付费或公司资格导致。

先由用户在 https://developer.apple.com/register/ 用同一账户尝试免费开发者注册；如有协议，由用户阅读并决定接受。仍失败再检查双重认证及账户资料，并尝试 Apple Developer App 或联系官方支持。该顺序依据官方流程整理，不是该错误的已验证修复法。未改账户、重复提交密码、发送客服消息或支付会员费。

依据：[开发者账户概览](https://developer.apple.com/help/account/basics/about-your-developer-account/)、[App 注册准备](https://developer.apple.com/cn/help/account/membership/enrolling-in-the-app/)、[官方支持](https://developer.apple.com/support/)。
