# Wearing 从 App 获取信息：当前能力与下一步

核对日期：2026-10-06。本文把已经实测、上游具备、仍需开发分开。手机型号只是验收设备，不是产品边界。

## 产品与工程决定

让 Hermes 根据需求选择人会使用的信息来源，再利用已接入设备操作 App。旅行可以需要攻略、真实评论、交通与库存信息，但这些不是固化的工具链或点击流程。Wearing 提供设备发现、观察、动作、媒体材料、记忆与运行回执；模型决定路径，并根据看到的新事实改变计划。

当前底座仍是一份 Hermes 工具循环。profile v13 接回原生 `todo_list`、skills 检索/加载/管理及 `vision_analyze`，保留已有 memory、session_search、web 和设备/生活工具。skills 与计划、视觉已经做过隔离模型测试；`skill_manage` 写入经验尚未实测。Hermes Gateway cron ticker 没有另启，时间与记录变化仍由 Wearing 的同一调度表唤醒 TaskService。

profile v14 新增 App 观察回执。读取 App 后，把连接器签出的设备资源编号、观察编号、查看时间、包名、可见文字绑定到原 run。截图单独记作取得画面，不能据此说模型看过，更不能说看完视频。界面提供默认折叠的「这次查看的依据」。本轮只接本地 `wearing_phone` 工具结果；云端远程设备通道的相同回执尚未适配。

## 实际信息能拿到什么

测试环境：小米 6X / Android 9 / USB；已有调试授权；当前游客状态。

| 来源 | 已实际观察 | 尚不能据此声称 |
|---|---|---|
| 小红书 | 搜索结果的标题、作者、相对发布时间与部分摘要 | 一次打开详情出现登录要求；完整正文和评论未验收 |
| 抖音 | 中文搜索、切换视频结果、打开公开视频详情和评论；原生屏幕文字；手机截图交给视觉工具解读 | 完整口播、连续字幕与整条视频理解未接通；热度不代表可信度 |
| 携程 | 本测试机未安装 | 没有验收实时票价、库存或下单 |
| 美团、淘宝闪购等 | 测试机已有相关应用 | 没有验收完整消费交易 |

真实模型搜索「泉州 旅游 避坑」后取得两条候选和一条视频的两条评论。评论只是简短反应，没有支撑具体避坑结论。该轮耗尽测试设置的 20 轮上限，只留下阶段总结；保持未完成状态。随后短任务完成「读当前页面 → 截图 → vision_analyze → 回答 → 网页回看依据」，见 [验收记录](../evidence/app-observations-2026-10-06.md)。这些是设备/阅读闭环的证据，不是一份已核实的旅游攻略。

## 多设备与视频路线

| 能力层 | 可复用方案与条件 | Wearing 状态 |
|---|---|---|
| 点击、滑动、启动应用、截图 | Mobile MCP；Android 原生文本观察与中文填写使用已固定 UiAutomator2 | 当前机型已实测。每次指定 resource_id，不能因离线悄悄换手机 |
| 页面过渡与输入核对 | 短暂空白/系统控件时有界再次读取；一次填写后读回 | 已实现。装饰性读回保留观察值和未知状态，不重复输入/自动提交 |
| 连续画面 | 优先评估 Mobile MCP 已有 screen recording 与 scrcpy | 尚未开放；上游 recording 走 MobileCLI，当前 legacy 通道不能直接假定可用 |
| 手机内部音频 | scrcpy 支持 Android 11+，12+通常可直接使用；11 启动时需解锁 | 未集成，未在新设备上实测。Android 9 不能使用这条音频路径 |
| 应用级播放录音 | Android 10+ AudioPlaybackCapture | 还需要录音权限、MediaProjection 同意、同用户空间及源 App 允许；不是升级系统就必然有声音 |
| 视频理解 | 有界录制 → 时间戳画面/音轨 → 转写/视觉 → 可回看材料 | 待开发；不是截一张图后把推测当完整视频结论 |

音频条件来源：[scrcpy 官方音频文档](https://github.com/Genymobile/scrcpy/blob/master/doc/audio.md)、[Android 播放音视频采集文档](https://developer.android.com/media/platform/av-capture)。版本条件只是候选能力，接入后仍要检查真实音轨、可解码帧与来源 App。

下一步实现限定时长的媒体采集适配器：每个租户/身份的私有材料目录、固定大小/时长、资源锁、停止与进程回收、真实媒体探测及时间范围回执。复用现有采集/模型组件，先在合成素材上验证，再用公开 App 验收。不让模型传任意主机输出路径，也不开放无人看管的无限录制。

## 小米 6X 刷机选项

读到的设备代号是 `wayne`，此前只读检查 bootloader 为锁定。刷机可作为专用 Agent 手机的实验路径，不能当通用用户接入的前提。

本次检查，[LineageOS 的 wayne 设备条目](https://raw.githubusercontent.com/LineageOS/lineage_wiki/main/_data/devices/wayne.yml)只列出 17.1/18.1，维护者为空；[PixelExperience 的 wayne 页面](https://wiki.pixelexperience.org/devices/wayne/)明确已停止维护。因此还没有选定可推荐的当前 ROM。不能把 Mi A2/jasmine_sprout 等相近硬件当作同一刷机包。

下一台优先用于验收 Android 12+ 的普通原厂系统；并行研究此机的准确 ROM、来源/哈希、当前解锁资格、完整备份和原厂恢复路径。到具体解锁/清空前再交接确认。本轮没有解锁、刷机、Root、清空数据或修改账户。
