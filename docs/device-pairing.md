# 设备接入与卡点核对

云端网页的连接设置现在提供“接入新的电脑或手机”。它接收连接器导出的设备清单，显示当前身份已接入的设备，并让用户选择设备和权限。Android 默认只读，可明确选择读取、点击与输入；电脑可选择观察或逐次确认点击与输入。服务端只使用自带的固定工具定义，不接受清单上传的工具、脚本、云端地址或凭据。

在已完成本机准备和授权的 Mac 或 Windows 上运行：

```sh
wearing connector inventory --data-dir 本机数据目录 --offer --output wearing-devices.json
```

导入清单、选择权限后，网页下载十分钟一次性的 `wearing-pair.json`。设备所在电脑运行：

```sh
wearing connector pair --root 新连接目录 --data-dir 本机数据目录 --bundle wearing-pair.json
wearing connector service install --root 新连接目录
```

本机再次验证设备 ID、类型和权限上限，才会配对。连接器只主动连接固定的 HTTPS 设备入口，不开放本机端口。配对请求可用同一请求 ID 恢复丢失的响应；重复绑定已有资源会被拒绝。配对文件含短期配对码，需要私有保存，不包含模型 Key 或长期连接令牌。当前云端设备会话会自动收到能力变更通知；新接入同类设备从实时清单选择即可。已有电脑的权限可通过[权限变更](device-permissions.md)升级或降级，无需重新配对。

云端入口管理员需要配置实例的 `data/device-endpoint.json`，只含 `endpoint` 和 `ca_pem`。既有 `tenant pair-device` 命令会保存该配置。用户上传清单不能更改它。新电脑持久化独立设备 ID，首轮试验机器保留旧 `computer_local` 绑定。

设备动作结果不明或报错时，设置页显示核对记录，同时阻止该设备后续点击、输入等动作。读取仍可用于查证。只有原动作有效期已结束、连接器提供此后的心跳、设备在线且没有进行中的设备动作时，网页才允许确认。用户必须说明实际结果，并确认已查看设备和旧动作已结束。确认在事务内检查记录版本、保存核对文字及来源，仅解除后续操作的阻塞，不重发原动作，不将业务任务自动标为成功。迟到回执不能覆盖已核对记录。

常驻安装后无需保持终端打开，在当前用户登录后运行。查看、停止或重新启动用 `wearing connector service status|stop|start --root 新连接目录`；停止会等当前动作交回回执，保留配对与账本。细节见[连接器常驻](connector-service.md)。

当前仍需命令行安装和本机权限准备；Windows 常驻目前完成代码与契约测试，未做真机验收，iPhone 尚未开放。该向导不替代首次系统授权、生产证书轮换或正式 SaaS 登录。
