# Wearing 的个人记忆

2026-10-03，profile v6。本地第一版复用固定版本 Hermes 的 `memory` 与 `session_search`，没有另建记忆数据库、向量索引或后台 Agent。

## 怎么用

在对话里说「帮我记住……」。稳定的偏好放在用户档案，已验证的经验放在经验记忆。纠正时直接说「那条记忆改成……」；Wearing 的指令要求通过 replace 更新原条目，并且只在工具确认保存后反馈成功。

右上角「一起记着的 → 记着你的」读取当前身份实际保存的条目。「这条需要纠正」把原文带回输入框，由你补充并发送；已有草稿不会被覆盖，也不会自动发出。纠正后用「重新查看」核对。未启动的身份显示不可读取，查看记忆不会替它启动另一个引擎。

以前聊过但没有整理为偏好的细节，可以说「帮我查一下之前聊过的……」。模型使用 Hermes 的关键词检索和会话读取工具，返回当时的原话及出处；没有找到不应猜测。它不是全量语义搜索，也不保证任意中文表述均命中。

## 保存与上下文

- 每个身份使用自己的 Hermes Home，原生 `memories/USER.md` / `MEMORY.md` 保存条目。普通对话与目标步骤都使用同一引擎配置。新一轮 Agent 从该身份的原生记忆加载上下文。
- 原生默认字符预算：用户档案 1,375，经验记忆 2,200；用户自定义限制和关闭设置保留。超出预算的整理与拒绝沿用上游实现，不宣称可以无限记住所有事情。
- 历史对话留在该身份的 Hermes SessionDB；目标约定与补充留在 Wearing 数据库。历史搜索只覆盖实际进入该引擎的会话，不覆盖未发送草稿或全部设备内容。
- 只读记忆接口受执行引擎连接密钥保护，Wearing 页面沿用身份与本地来源检查。返回原生条目，页面按纯文本转义显示；不能直接经此接口改写记忆。

记忆是模型整理的记录，可能记错；它不构成新的用户授权，也不代表外部业务已经验证。密码、验证码、API key 与支付凭据不应写入记忆。当前页面没有彻底遗忘入口：删除一个原生记忆条目不会删除历史会话和备份，不能当作全量数据删除。后台 curator 与自动清理仍关闭。

当前身份分区属于同一用户的本地使用场景，不能替代 SaaS 租户隔离。云端仍按每租户独立 VM/microVM 规划，尚未部署。验收范围见 [个人记忆验收](evidence/personal-memory-2026-10-03.md)。
