# 持续推进后的反馈

更新于 2026-10-04。已接到目标调度、原任务结果与私人云端网页，不依赖网页一直打开。

每轮目标收取结果时，会把目标状态、报告和一条反馈在同一数据库事务中保存。执行下一轮、等待、需要用户决定、等待核对或用完轮次，都有对应记录。异常或无有效报告的轮次会留下需要复盘的反馈。修改或暂停后才返回的旧步骤保留历史，不替新方向发提醒。

回来时，对话上方出现轻提示，右上角「一起记着的」显示新进展数量。打开后可查看结果与当前目标状态。「看看进展」打开对应目标并将这一条标为已读；「知道了」只标已读。「这些都看过了」只处理当前显示的最多 20 条，随后可查看更早记录。

读过不表示完成或授权继续。目标需要用户决定、核对或增轮的状态保持不变。目标已修订时，旧反馈会显示当前状态，避免旧提醒被误认为当前安排。完整报告与依据仍在目标进展和原对话中；模型报告并非已核验的业务成果。

## 持久性与接口

- `goal_updates.task_id` 唯一；与步骤已处理标记、目标状态同时提交。任一写入失败整笔回滚，下一次收取可以恢复。
- `GET /api/goal-updates` 返回当前身份的未读数量与最近 20 条，不自动标记已读。
- `POST /api/goal-updates/seen` 接收明确的记录 ID；需有效网页会话及原身份，跨身份或未知 ID 整笔拒绝。重复请求幂等，不影响之后到达的记录。
- 网页初始化立即读取，显示时约每 12 秒刷新；关闭或隐藏网页期间不轮询，服务器照常保存。重新打开后读取数据库中的反馈。
- 这是各身份自己的网页内反馈，没有浏览器权限申请，也不发送到外部服务。系统推送、邮箱/短信投递和外部事件唤醒尚未接入。
- 新增表不回填历史已处理的轮次，避免更新版本后把旧测试记录当成新的进展。

轮次仍为执行次数上限，不是金额或 token 硬预算。持续反馈不新增模型调用，也不扩大设备授权。
