# Pro 回复解读：Wearing 的下一步整合方向

日期：2026-10-01。性质：Codex 对 Pro 研究回复的解读与建议，尚未视为用户确认的最终技术选型。

来源：[原 ChatGPT 对话](https://chatgpt.com/c/6abbdb43-56dc-83ec-9b3f-6f2bd4df92f9)。[完整页面正文与可见引用链接](evidence/chatgpt-pro-response-2026-10-01.txt)已保存。Pro 的研究与本轮复核均不包含真机接入或真实业务验收。

## 核心判断

Pro 推荐先验证 Hermes 主 Agent + 电脑/手机/服务执行工具；OpenAgentCore 使用现成引擎做对照，证明环境管理与恢复收益后，再考虑限定任务委托或 Hermes 原生适配。

我赞成这个验证顺序。最有价值的分工是：成熟 Agent 负责理解、计划和调用工具；Wearing 整理实际可用资源、接入步骤、操作结果和恢复方法。OpenAgentCore 的采用与否应服务于真实任务，不成为软件探索的前置条件。

## 值得吸收的四点

1. **分开设备、任务、模型运行的寿命。** 设备和账号可以长期存在；一件事务可以跨几天、多次运行；每次模型结束不代表事务已完成。持续资源与业务事实要能跨会话引用。
2. **同一个人可以有多种执行资源。** 主 Agent、执行电脑、App 手机和承载号码的设备可以分开。连接器记录实际能力和环境，不要求所有东西放在一台机器。
3. **Computer Use 和手机控制是实际执行路线。** 按具体任务比较成功率、成本和维护负担；API、浏览器、桌面和手机允许混合使用。
4. **把完整使用方法变成可复现成果。** 包括资源取得、配置、操作、维护、恢复和退出；“已连接”只是一种中间状态。

## 本轮独立复核的两处

### Hermes 已有程序化接入说明

Pro 引用的提交可解析为 `1ce2cfb7facc4a6f36098fcc4a8860ed8a445e41`。该提交官方文档明确列出 ACP、TUI Gateway JSON-RPC、HTTP 接入，以及 runs 的状态、SSE 事件、审批、steer、stop 等入口。Wearing 可以先围绕已有入口验证自己的界面和流程。

文档也说明，steer 返回成功表示排队，不保证已被消费；completed 表示该轮生成最终答复。两者都不能替代业务结果核对。本轮单独读取路由源码时遇到 429，因此这一项记录为官方文档和文件存在性核验，未完成全部路由实现复审。

[固定版本的程序化接入文档](https://github.com/NousResearch/hermes-agent/blob/1ce2cfb7facc4a6f36098fcc4a8860ed8a445e41/website/docs/developer-guide/programmatic-integration.md)

### Open-AutoGLM 的完成状态需要外部核验

Pro 引用的提交可解析为 `86f55382982fb054e8fc98ca80609dff8a2cdc3c`。源码确认：解析异常会转换为 finish；部分动作执行异常也进入 finish 路径；动作处理器对 finish 返回 `success=True`。因此执行器的结束状态需要保留原始原因，Wearing 根据目标状态决定是否完成。

点击动作的确认回调受动作中的 message 字段触发，不能推断所有敏感操作都会自动得到确认。Note 与 Call_API 还有占位实现。接入时要测试具体动作，不能按工具名推断能力。

来源：[主循环](https://github.com/zai-org/Open-AutoGLM/blob/86f55382982fb054e8fc98ca80609dff8a2cdc3c/phone_agent/agent.py#L190)、[动作处理](https://github.com/zai-org/Open-AutoGLM/blob/86f55382982fb054e8fc98ca80609dff8a2cdc3c/phone_agent/actions/handler.py#L61)。这些是源码事实，尚未在目标设备复现。

## 我会保留的三个修正

- **自建部分随真实缺口逐步增加。** 资源档案、业务任务记录、费用、设备占用与接管可以先用少量文件和程序完成。已有框架能满足的部分直接复用，再按实测缺口补充。
- **操作配方保留通用 Agent 的探索空间。** 配方主要沉淀取得、配置、使用和维护资源的方法，以及可复用经验。新目标仍由 Agent 理解与探索，不要求先给每件事情编写固定工作流。
- **取得资源和验证操作同步推进。** 电话、支付等尚未确认的条件要形成明确调查任务：要向谁查、缺什么证据、有什么其他路线。软件实验可以先开展，资源获取也是项目核心工作的一部分。

Pro 对号码、U 卡、地区和金融产品给出的具体资格或费用，本轮未逐条重新核验，保留为外部研究线索。不会把它们直接更新为已可用或最终排除的接入路线。

## 建议的近期推进方式

| 工作线 | 下一份有意义的产出 |
| --- | --- |
| Agent 与电脑 | 在实际 Mac 上确认 Hermes 的安装、程序接口、浏览器/桌面工具、文件与中断恢复；版本固定 |
| 手机操作 | 同一设备、同类任务对比 Mobile MCP 与 Open-AutoGLM；记录真实结果、接管和恢复 |
| 资源获得 | 邮箱、电话/SMS、支付分别形成适用条件与完整办理路线；区分未确认、已取得和实际可用 |
| OpenAgentCore | 用现成引擎开展相同任务的对照，验证环境与恢复管理是否值得多运行一套服务 |

先保留完整能力地图，按依赖选择第一批实验。各条路线记录真实资源、接入方式、操作证据和故障处理，逐步接成同一个 Wearing。当前没有开始安装、开户、模型调用、Root 或付款。
