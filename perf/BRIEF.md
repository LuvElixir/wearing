# iPhone 语音输入性能 · 2026-10-07

- 体验：按住说话 → 松手 → 文字进入可编辑草稿。用户明确反馈识别慢、不准、重复加载反馈及 SQLite 锁冲突。
- 第一指标：松手到可编辑文字草稿的回执耗时。分段记录 stop / save / copy / upload / transcribe / ack。
- 当前环境：iPhone Air + Expo Go，可信局域网连接 Mac；本机 faster-whisper small/int8、4 threads、beam 5、VAD。开发模式与正式包分别验收。
- 本轮范围：消除存储竞争、重复回执写入、每次启动识别器的开销；输入栏单一识别反馈，原生线程动画；修复识别结果二次过滤造成的漏段。
- 不能改变：取消不上传；原件先于识别；后台及身份切换不误投文字；显式发送；持久化失败不可谎报成功。
- 测量：同一合成中文 8 秒音频，旧冷进程与新暖进程 10 组交替配对，首次新进程单列。记录 p50/p75/p95、内容一致性、版本与哈希。
- 目标门槛：复用模型应降低服务端转写耗时，不能改变同一有效音频的文本；SQLite 并发回归通过。真实口音、人名、地名的正确率和 iPhone 端到端 p95 不从单条合成语音外推。
- 后续体验目标（未达成）：流式录音传输重叠计算，缩短松手后的等待；使用经测量的中文识别方案和必要热词。没有启用新的付费服务或向第三方传输用户录音。
