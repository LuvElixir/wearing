# 设备文件传递

本轮目标：在已接入设备的详情里，把当前身份工作区的一份文件送到设备固定收件目录，或把设备固定结果目录的一份文件取回工作区。云手机开通、安装应用、任意目录浏览和公开分享不在此入口内。

## 客户端状态契约

| 阶段 | 展示与允许操作 |
| --- | --- |
| 尚未读取 | 显示读取中；不把缺少回执当成空目录或可用能力。 |
| 不支持或暂不可用 | 展示服务返回的可用性原因；私密接管期间不能触发传递。 |
| 选择文件 | 只使用服务返回的文件条目；展示名称、大小和固定目的地。 |
| 请求已记录 | 先保留当前账号、身份、设备和请求标识，再发起一次传递。 |
| 等待或传递中 | 只展示真实阶段；没有服务端字节进度时不显示虚构百分比。 |
| 回执未知 | 保留原请求标识，只查询原请求；重新打开页面、恢复前台、网络重连不重发。 |
| 停止本机等待 | 仅在服务标明未知或连续两次查询原回执为 404 时显示。需再次确认，不取消设备动作；精确删除本账号、本身份、本设备的这份等待记录并读回确认。再次传递须重新选择和确认。 |
| 已完成 | 仅在匹配原请求、设备、身份和文件的完整服务回执后显示成功。取回结果提供工作区入口。 |
| 明确失败 | 展示固定错误文案。源文件变化时重新选择；再次传递必须是用户的新动作。 |

## 实现约束

- 凭据只在现有认证请求头中，客户端快照包含账号会话；切换身份或离开页面后丢弃过期异步 UI 更新。
- 不保存或记录文件内容，不在错误日志里带原始服务响应、文件内容、系统绝对路径或凭据。
- 重启恢复只持久化有账号、身份、设备范围的请求元信息，沿用账户清理规则；不下载文件到 App 再转发。
- 客户端大小/文件名校验用于反馈；固定目录、权限、源版本、摘要和所有权由服务再次验证。
- 传递成功只表示文件已到达指定位置，不代表目标应用已打开文件或已完成用户任务。

## 已接入的服务合同

所有路由使用现有原生会话请求头及当前身份；写入使用 bootstrap CSRF，不把 token 放入 URL。

| API | App 行为 |
| --- | --- |
| `GET /api/devices/{rid}/files` | 读取 `supported/available/reason/max_bytes` 与固定 Inbox/Outbox 标签；`files_permission_required` 显示尚未开通文件权限。 |
| `POST .../workspace-source` | 用户从分页工作区文件列表选中条目后，请服务建立不可变快照；得到文件 ID、名称、大小、SHA-256，展示确认卡。 |
| `POST .../transfers` | 本机先记录随机请求 ID，再显式提交一次 `to_device/from_device/list`。目的目录和名称不可编辑。 |
| `GET .../transfers/{request_id}` | 按原 ID 查询；任何 POST 异常，包括 4xx/5xx/网络中断，均不自动重发。GET 404 仍表示未知。 |
| `GET .../transfers` | 展示最近服务记录；列表内容明确标记为“上次读取的结果”。 |

源文件为 1 字节至 20 MiB（20,971,520 字节），包含两端；空文件不支持。名称必须为 NFC，1 至 180 UTF-8 字节，无首尾空白、前导点、路径分隔符和控制字符。取回成功须同时有与原请求匹配的设备、文件摘要、完成字节数及工作区文件回执；之后才提供“在工作区查看”。

请求恢复键为 `device-file-transfer:v1:<account-and-identity-scope>|<resource>`。删除与账户清理共用原生 SQLite 队列，并使用 `DELETE ... WHERE key = ? AND value = ?` 比较原记录，不能清除同时更新的新请求。账户冻结、导航离开与晚回执均不得重新创建已清理的键。停止本机等待不会删除服务历史，也没有取消或重发 API。

## 本轮验证与边界

模型、API 与实际组件处理函数测试覆盖：会话快照、未知响应后仅 GET 恢复、HTTP 4xx 不推断未提交、重复点击、导航离开、账号注销、精确回执、文件大小与 UTF-8 名称边界。实际原生存储函数在真实 SQLite 上验证并发替换的 CAS、账号清理竞争、只读数据库拒绝删除与删除后读回。

2026-10-10，后端文件通道已部署到 A/B 测试环境，并在专用 **Pajio Acceptance iPhone Air 模拟器的 Release App** 中完成 A 账户 `daily` 身份的真实界面验收：

| 设备 | 通过 App 发起的操作 | 独立核对 |
| --- | --- | --- |
| A Linux 电脑 | 选择工作区 96 KiB 合成文件并发送、读取 Outbox、取回并打开工作区入口 | 三份原请求回执均为 `completed`；取回文件下载为 98,304 字节，SHA-256 与合成源一致。 |
| A Android 云手机 | 选择同一合成文件并发送、读取 Outbox、取回 | 三份原请求回执均为 `completed`；取回文件下载为 98,304 字节，SHA-256 与合成源一致。 |

操作员在 App 中执行操作后，独立验收仅 GET 原请求回执并下载已知合成结果核验，没有再次提交传递。证据分别为 [Linux 回执](../../../docs/evidence/pajio-device-files-ui-20261010/linux-receipts.json)与 [Android 回执](../../../docs/evidence/pajio-device-files-ui-20261010/receipts.json)。记录中的界面观察时间精确到分钟或为近似值，文件修改时间也不代表传递总时长。

这证明模拟器中的真实原生 App 到已部署 Linux/Android 设备文件通道可用；**不等于物理 iPhone 或 Android APK 手工验收**。B 两台设备的 20 MiB 边界传递、A/B 跨账户拒绝和私密接管期间拒绝，属于独立的 [API/设备验收](../../../docs/evidence/pajio-device-files-2026-10-10.md)，不是本轮 App 界面逐项复验。网络结果未知后只查询原请求、不重复提交，目前由单元与实际处理函数测试覆盖，尚未在真实 App 上注入断网或服务端提交后响应丢失故障。

此入口不提供云设备自动开通、排队、应用安装、任意目录浏览或公开分享。首次无设备时仍依赖运营开通及现有接入流程。
