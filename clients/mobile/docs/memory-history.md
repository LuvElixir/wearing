# App 个人记忆修改记录

2026-10-10。范围为 App 原生界面与既有 `/api/memory` 客户端；服务端契约见 `docs/memory-management.md`。

## 用户能做什么

「关于你」和「长期记忆」各自展示「你的修改记录」，默认最近三条，可展开服务器返回的最近二十条。列表显示真实操作与时间，详情只对比加入和移除的条目。来源明确限定为用户在产品中做的修改，不称为全部模型记忆审计。

仅服务器声明 `undoable`、页已启用且记录 revision 与当前页相同，才允许撤销。用户核对确认后发送 `history_id + 当前 revision`，取得完整新快照后才显示成功。暂停时可以看记录，不能用撤销恢复内容；旧服务未返回 history 时没有撤销入口。

清空确认列出身份、目标页、条目与记录数，明确同时删除本页修改记录且无法撤销；本机未保存草稿、另一页、其他身份、对话和文件保留。普通删除和清空是两个不同操作。

## 请求与不确定结果

- 修改不会自动重放，包括 token 刷新触发的 403。返回 409 时只重新读取一次，保留编辑草稿，请用户核对后自行操作。
- 网络中断或不完整响应不被当作失败退款式回滚，也不被当作成功。界面要求先读取最新版再继续修改。
- 服务端 `unconfirmed_changes` 单独显示待核对提示，未确认记录不进入已完成历史。
- 历史标识、页 revision、来源、记录边界与完整响应均校验。旧服务缺少可选 history 仍可读取。

## 验证

全套 `src/*.test.ts` 共 768 项通过；新增九项历史测试覆盖来源与标识校验、重复文本差异、跨页/过期/暂停撤销、延迟响应无乐观成功、409 只读刷新、不确定结果不重放、403 不重放、完整清空快照替换。既有草稿测试继续通过。TypeScript 与项目 ESLint 通过。

原生 Release 已在独立 iPhone Air / iOS 27 模拟器安装并通过公网 OAuth 登录 acceptance-a，保留原 QA 模拟器与连接。真实新增 1 条合成记忆 → 查看修改详情 → 明确确认撤销 → 服务端返回 0 条，历史留下 add / undo；再次打开原新增记录没有撤销按钮。清空确认正确显示 0 条内容、2 条记录，未执行不可恢复清空。

原生验收修复了两个问题：服务端 PATCH 缺少 json 导入（由服务端任务处理）；App 同一帧关闭详情 Sheet 并打开另一个确认 Sheet，导致 iOS 确认窗口不显示。现为同一个 Sheet 内切换内容，已在真实原生运行时验证确认与撤销回执。初次 500 后草稿保留，先读取再由明确点击重新保存，没有自动重放。

768 项模型测试不能替代真机测试；以上为 iOS 模拟器和公网合成账户验收，尚非物理 iPhone。证据位于被 Git 忽略的 `.wearing/on-prem/20261009/personal-compute/mobile-native-proof.json` 与 `mobile-memory-undo.png`。
